# 历史示例：地图拓展构想（不属于开发计划）

> 2026-10-23 更正：用户明确地图解锁仅为例子，不承诺采取。本文撤销 V2.0 排期与版本需求地位；下文原草案仅为历史讨论，所有“必做”、版本号和验收均不生效。不得据此安排开发。实际扩展在后续选题后另写需求。

日期：2026-10-23　状态：规划草案，具体解锁规则待冻结

## 1. 目标与继承范围

在已验收的 V1.0 上，使玩家获得物品或钥匙后能打开新区域，扩大同一局的游戏空间。继续支持两台 Android 手机、电脑权威服务器和局域网双人对抗。

继承 V1.0 的移动、光照、标记、保护状态、单件任务物资携带、交互取消、胜负优先级和异常判负规则。地图范围、点位与任务分布可以变化，但必须记录差异并重新验证可达性与对局时长。V1.0 的 180 秒先作为试玩起点，不承诺扩大地图后仍然平衡。

## 2. 版本边界

| 分类 | 范围 |
|---|---|
| 必做 | 一个含锁定区域的地图配置、明确解锁条件、服务端解锁判定、双方一致的门/碰撞状态、提示、重置与死锁检查 |
| 候选实现 | 一个初始区域＋一个锁定区域、一把专用钥匙、一扇门；用于控制首个拓展版本规模 |
| 本版排除 | 多层世界、跨服务器切换、动态下载地图、随机迷宫、多个复杂钥匙链、战斗道具、传感器功能 |

用户提出的“物品或 key”是方向，不等于已经选择专用钥匙。下节以钥匙开门提供可评审的具体起点；若选择“拿到任务物品直接解锁”，需替换钥匙相关规则和验收。

## 3. 候选玩法规则（建议，未确认）

| 编号 | 建议规则 |
|---|---|
| Z01 | 地图包含初始开放区和一个锁定区；锁定区由实体墙/门封闭，未解锁时双方都不能穿过，门也阻挡光线 |
| Z02 | 钥匙固定生成在初始区域，开局可达；仅小偷可按 V1.0 的 0.8 格、无遮挡、静止按住 1 秒规则拾取 |
| Z03 | 钥匙独立于任务物资携带槽，持有一件任务物资时仍可获取钥匙；钥匙不主动丢弃，标记不会使其掉落 |
| Z04 | 持钥匙的小偷在门前按住 1 秒解锁；松手、移动、被标记会取消；真正隐身禁止拾钥匙和开门，免疫期间允许 |
| Z05 | 解锁成功消耗钥匙，门永久开放至本局结束；双方均可通过；重复开门请求不重复消耗或提交事件 |
| Z06 | 一个任务物资或其交付点放在锁定区，保证开放区域对完成游戏有作用；钥匙和开门所需条件不得放在其自身锁定区域内 |
| Z07 | 仍为三组取送、两个出口，第三次交付后两个出口开放；撤离条件不额外增加“持有钥匙” |
| Z08 | 门状态为双方公开信息；不向警察额外广播钥匙拾取位置、持有人位置或轨迹；小偷显示自身钥匙状态 |
| Z09 | 暂沿用完整静态小地图，显示区域边界与门锁定状态；不新增探索迷雾；隐藏对手规则仍按 V1.0 |
| Z10 | 本局结算后所有解锁操作失效；新局门重新关闭，钥匙恢复初始位置，任务与角色完全重置 |

门开启使碰撞、视线和可达范围一起更新。与第三次标记、超时等事件同一模拟步发生时，先遵守已有标记中断和结局优先级；结束后不得继续改变区域状态。

## 4. 页面与网络要求

- 小偷界面增加钥匙持有提示，交互按钮能说明“拾取钥匙”“开门”或缺少条件。
- 双方显示明确的门开闭状态；开门提示不得额外暴露隐藏的小偷坐标。
- 服务端校验钥匙归属、距离、遮挡、状态、连续交互时间；客户端不直接提交成功结果。
- 快照提供客户端有权看到的当前区域/门状态；不能只依赖一次开门动画或一次事件，避免客户端漏掉动画后仍把门当墙。
- 不扩展 V1.0 的断线重连承诺；地图状态随正常快照同步与重置。

## 5. 验收标准

以下以第 3 节候选方案被采用为前提；方案调整时同步改验收，不将草案用例当作已确认承诺。

| 编号 | 场景与通过标准 |
|---|---|
| ZA01 | 双方开局均不能穿过锁门，不能隔门照明或交互；钥匙在初始区可达 |
| ZA02 | 持任务物资时可拾钥匙，任务物资不丢失；警察不能拾钥匙 |
| ZA03 | 无钥匙不能开门；有钥匙但隔墙、移动或隐身时不能完成；取消后进度清零 |
| ZA04 | 合法开门后两台手机门状态一致，双方可以通过，光线按开放后的地图判断 |
| ZA05 | 重复请求不会复制钥匙、重复消耗或关回已经打开的门 |
| ZA06 | 在新区域完成任务并按原规则撤离；三次标记和超时仍能正常结束 |
| ZA07 | 钥匙、门与任务不存在循环依赖；从初始状态有一条合法完成全部任务和撤离的路径 |
| ZA08 | 警察数据中没有通过钥匙字段泄露隐藏小偷的位置，旧视野权限测试仍通过 |
| ZA09 | 开门期间被标记/掉线/结束时状态正确；下一局恢复锁门与钥匙，不残留上局状态 |
| ZA10 | 对新增地图记录多轮换边试玩中的到达时间、交付时间与守门现象，据此决定是否调整 180 秒等参数；未经记录不声称平衡已完成 |

## 6. 交付物和进入开发的条件

交付可运行客户端与服务端、新地图数据、解锁配置、规则差异记录和 ZA01–ZA10 验收记录。原地图保留作为回归用例；是否给玩家提供地图选择页面另行决定，不自动扩大范围。

开发前必须确定：区域解锁还是关卡切换、钥匙还是任务物品触发、钥匙是否独立携带和消耗、警察通行权、地图布局、提示公开程度。确认这些决策后将状态改为开发基线；不需要在 V1.0 开始前全部决定。
