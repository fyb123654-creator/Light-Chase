# Light Chase 本轮开发需求与开工说明

2026-11-17。本轮在现有局域网双人追捕游戏中加入道具、单向传送和独立瞄准。原有取送物资、标记、撤离、超时、结算和重开继续验收。共享代码基线已就绪，玩法接入从本轮开始。

## 拉取并开始

在自己的 Light-Chase 仓库中执行以下命令。新成员先克隆[团队开发仓库](https://github.com/fyb123654-creator/Light-Chase)。各自在更新后的 main 上创建自己的功能分支。Windows 工程环境按[工程运行说明](../../README.md)配置。

```powershell
git switch main
git pull --ff-only origin main
.\gradlew.bat :client-network:test :game-data:test
```

## 玩家应能做什么

| 机制 | 本轮验收行为 |
|---|---|
| 拾取与双槽 | 靠近可用目标，静止按住交互键拾取。优先最近的可执行目标，同距按稳定 ID，开始后锁定目标。移动或松开取消。每人两个道具槽，同类也各占一槽，满槽时道具留在地面。 |
| 警察道具 | 加速与光照强化可以同时生效。光照只增加实际照射距离，画面同步。同类效果仍有效时拒绝再用，第二件留槽。 |
| 小偷道具 | 加速、护盾均可在移动时使用。护盾先于本步照射生效，取消交互、清空累计照射，保留已成功标记次数。保护期间仍可消耗护盾，剩余真隐身取现有剩余和道具时长的较大值。原标记免疫截止不顺延。真隐身可移动、使用已持有道具，禁止拾取、交付、撤离、解锁及进入通道。 |
| 卡与通道 | 两条单向通道、四个端点，各配一张卡。小偷卡槽独立、容量一张，不能丢卡或换卡。入口按住解锁，匹配才销毁卡，本局永久开放。松开重按才传送，可携任务物资。传送中禁止移动、交互、用道具，不受地表照射，计时继续。落地无额外保护或冷却。 |
| 可见信息与小地图 | 双方右上角显示地图、自身红点、公开通道及状态。地面道具和卡的位置及拾取消失公开，背包、卡槽私有。每次传送提示警察，双方看到同一光球沿直线从入口到出口。落地立即移除光球，重新按视野显示对手。 |
| 警察瞄准 | 左侧控制移动。游戏外关闭陀螺仪时，右侧摇杆瞄准，松开保持方向；开启时右侧为校准按钮。校准依次取当前移动方向、最近移动方向、出生朝向，同时重设手机姿态基准。无传感器时使用触控。 |

道具和卡先固定生成，使用共用测试配置。随机生成、正式地图布局和数值平衡留到功能联调后。详细边界见[组员版功能说明](2026-11-16_组员版功能拓展说明.md)，字段、权限、失败反馈及同一步处理顺序以[接口契约第 13 节](../development/02_接口契约.md)为准。

## 每个人的第一项交付

| 成员 | 代码范围和第一项任务 | 独立通过标准 |
|---|---|---|
| A 游戏逻辑 | 在 game-core 接入 v2.MatchEngine，读取共享配置，先实现移动与照射方向分离。 | 用固定 tick 输入向右移动、向左照射，验证角色位置和实际光照判定，再接入双槽和效果。 |
| B 网络 | 在 client-network、server 接入 v2 网关和编解码器，先贯通输入、使用道具及本人回执。 | 用假引擎和两个 JVM 客户端验证按角色发送视图、重复操作只执行一次、旧请求不能扣除新道具。 |
| C Android | 在 client-core、app 建立脚本化假网关，先做左右摇杆、两个可点击道具槽。 | 用共享快照显示两个同类道具，分别点击能发出对应槽位和实例 ID；左侧移动不覆盖右侧瞄准。 |

共同依赖、源码入口和构建命令见[共享代码接入说明](../development/13_R3共享代码基线与接入说明.md)。联调按独立瞄准 → 双槽与护盾 → 拾卡和解锁 → 单向传送及小地图 → 真机陀螺仪 → 整局与重开推进。各阶段通过标准见[分工与联调表](../development/11_功能拓展分工与联调.md)。
