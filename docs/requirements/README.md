# Light Chase 当前范围与文档索引

日期：2026-10-23；修订 R2。

## 1. 当前确认范围

只规划 V1.0 基础联机版：两台 Android 客户端通过电脑 Java 权威服务器，在局域网完成追捕、物资取送、撤离及结算。用户本轮确认沿用 Java、Android Studio、libGDX、WebSocket 和现有 V1.0 玩法，并允许补齐实现建议值。

地图解锁、钥匙和传感器只是用户举例，并未确定采用。此前将其安排为 V2.0/V3.0 的规划已撤销；历史草案保留以追溯，不具有当前需求或排期效力。后续通过试玩选择真正有趣的新功能，再单独写需求。

## 3. V1.0 内部里程碑

开源参考也纳入开发范围管理：见[开源复用方案](../development/06_开源参考与复用方案.md)及[登记表](../development/07_开源复用登记表.md)。Fugitive 2D为优先研究候选，尚无已复用代码；已确认Java/libGDX路线不变。

| 节点 | 功能 | 完成要求 |
|---|---|---|
| M1 工程与连接 | 统一工程、契约、双端连接、房间、角色、准备、倒计时 | 两客户端进入同一房间；各模块有独立替身；记录构建环境 |
| M2 移动与追捕 | 地图、碰撞、镜头、权限、光束、标记、保护和超时 | 两端状态一致，警察获胜路径可用，隐藏信息不发出 |
| M3 完整闭环 | 物资、交互、丢弃、交付、出口、HUD、小地图、异常处理、结算重开 | A01–A22及补充用例通过；未测设备项显式记录 |

开发设计中的S0–S5是这三个里程碑的更细任务阶段，不是新产品版本。先使用双模拟器联调；真机验证未完成时不能宣称真机验收已通过。

## 4. 范围和协作管理

用户负责游戏规则及权限投影；B负责服务器、房间、客户端网络适配与协议；C负责Android界面、输入、渲染及生命周期。无固定截止日期，按可验证产物持续推进。具体依赖版本、正式地图、设备与包名按决策清单在对应阶段落实。

当前已有可构建的 S0 骨架及部分 S1 原型，详见 [骨架运行与交接](../development/08_骨架运行与交接.md)。Android 为离线展示，真实联网仅验证到 JVM 大厅；M1–M3 均不能标记全部完成。文档中的完整验收项仍是后续目标。
