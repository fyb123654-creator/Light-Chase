# 历史示例：传感器构想（不属于开发计划）

> 2026-10-23 更正：用户明确传感器仅为例子，不承诺采取。本文撤销 V3.0 排期与版本需求地位；下文原草案仅为历史讨论，所有“必做”、版本号和验收均不生效。不得据此安排开发。实际扩展在后续选题后另写需求。

日期：2026-10-23　状态：探索草案；尚未选定传感器及玩法

## 1. 目标

为现有联机对抗增加一项可解释、可验证的手机传感器功能。其价值应能说明为更自然的操作或有意义的玩法选择，不能仅为展示传感器而破坏正常游戏。

基础对局继承前序已验收版本。传感器关闭、设备不支持或输入中断时，仍须提供可完成同等动作的触控方式。V1.0 不需要为此申请权限、采集数据或增加设置按钮。

## 2. 候选方案和选型门槛

| 候选 | 游戏作用 | 主要需要验证的问题 |
|---|---|---|
| 手机倾斜辅助警察瞄准 | 从手机姿态产生手电朝向输入 | 横屏持握、校准漂移、抖动、移动与瞄准并行的可操作性；会改变 V1.0 的移动朝向规则 |
| 摇动触发一个明确动作 | 把手势转换为一次离散操作 | 走动误触、阈值、触发频率；必须先有合理动作，不能因选择摇动就擅自新增技能 |

建议优先做“倾斜辅助瞄准”的小实验，但不视为已经选定。具体传感器来源应根据目标手机实测决定，不预设所有手机都有同一硬件或行为一致。先只集成一种方案，不同时加入多种输入。

选型记录至少包含：使用的设备与能力、具体动作映射、触控替代方式、校准/阈值方案、误触和持握观察、与原规则的差异。若无法说明价值或稳定性不足，保留为实验，不强行计入完成版本。

## 3. 无论选哪种方案都必须满足的需求

| 编号 | 需求 |
|---|---|
| S01 | 进入相关模式前检查能力；不支持时给出清楚提示并使用触控，不影响房间加入 |
| S02 | 提供明确启用/关闭入口，默认关闭；用户关闭后不再使用传感器控制动作 |
| S03 | 连续输入方案必须支持中立位置校准、死区和平滑处理；离散方案必须有阈值和重复触发抑制；具体参数由实验记录冻结 |
| S04 | 触控和传感器输入经过统一动作入口；两种输入同时出现时采用明确的优先规则，不能叠加成速度或频率优势 |
| S05 | 服务器只接受语义操作，校验允许状态、范围和频率；原始读数不能成为客户端自行判定命中或胜负的依据 |
| S06 | 大厅、倒计时、结算或后台状态不产生对局动作；切后台继续沿用原版判负规则，停止采样并清空输入 |
| S07 | 回到前台不能恢复已结束的局；重新开局时初始化传感器控制状态，避免旧姿态/事件残留 |
| S08 | 原始采样保留在设备本地处理，不默认上传或写入战绩；只访问选定功能确实需要的设备能力 |
| S09 | UI 显示当前控制方式与校准状态；提示不遮挡主要操作区域；校准不能暂停服务器比赛时间 |
| S10 | 不支持、关闭或异常时有功能等价的触控入口；不能让玩家因设备缺少传感器而无法使用本版必需能力 |

## 4. 若采用倾斜辅助瞄准，需增加的规则变更

本节是候选方案，不自动覆盖 V1.0。

- 警察移动与瞄准分离，替代“光束始终跟随移动”。小偷操作暂不改变。
- 建议增加触控瞄准操作作为等价输入；传感器只改变朝向输入，不增加射程、扇形角度、速度或标记次数。
- 没有有效瞄准输入时保持上次朝向；首次朝向来自地图配置。
- 触控瞄准优先；触控释放后，传感器须重新以明确规则接管，避免突然跳转。具体接管条件在实验后冻结。
- 朝向更新由服务器认可后参与光照判定；服务器仍负责 0.8 秒标记、遮挡及隐身/免疫。
- 若新增转向速率上限，触控与传感器使用相同上限，并补充参数与边界测试。不能只限制一种操作方式。

## 5. 验收标准

| 编号 | 场景与通过标准 |
|---|---|
| SA01 | 两台目标手机记录能力检测结果；不支持设备可通过触控完成对应动作及整局 |
| SA02 | 启用、关闭、校准或阈值配置可用；关闭后改变手机姿态不会产生动作 |
| SA03 | 正常持握和轻微手抖不会持续产生非预期动作；按冻结后的输入参数测试边界并记录结果 |
| SA04 | 触控与传感器同时操作时符合已定义优先规则，不出现速度叠加、双重触发或方向跳变 |
| SA05 | 客户端伪造超出合法范围的动作被服务器拒绝或规范化，不能绕过保护、倒计时或结算限制 |
| SA06 | 切后台、关闭控制、结束对局后停止相关输入；前台恢复和下一局不存在旧输入残留 |
| SA07 | 在传感器开/关两种模式下分别完整结束联机对局，双方结果和视野权限一致 |
| SA08 | 若采用独立瞄准，更新 V1.0 中朝向、警察右侧操作及 A05 验收；其余核心标记规则回归通过 |
| SA09 | 对相同地图和网络，记录开启前后的帧表现、状态同步和操作体验；出现明显卡顿、误触或疲劳时修正，不把“能读到数据”视为完成 |

## 6. 交付物与冻结条件

先交付独立实验和设备观察记录，再决定是否集成。正式版本交付选定玩法的需求补充、参数表、客户端与服务端更新、触控替代说明以及验收记录。

集成前必须明确：选用的传感器功能、作用角色、动作映射、输入优先级、校准与阈值、设备覆盖及相对旧版的规则差异。未明确前可以做实验，但不能把本草案当成完整可执行的最终玩法规格。
