# Light Chase 三人任务书与 AI 交接说明

日期：2026-10-23；R1。以下文本可分别交给三位开发者及其AI助手。文中七个模块与 docs 目录均已创建，S0 骨架可构建、可运行；各任务的实际完成情况以 [08 骨架运行与交接](08_骨架运行与交接.md) 为准，不要把本任务书当成“全部已完成”或“全部待创建”。

## 1. 所有人共用的启动说明

把项目仓库与完整 docs 目录一并交给AI，不能只给聊天里的分工摘要。要求先阅读：`docs/development/README.md`、`01_分工与开发设计.md`、`02_接口契约.md`、`03_联调与验收手册.md`、`04_决策与待确认事项.md`，以及`docs/requirements/V1.0_基础联机版需求.md`。

明确限制：只实现V1.0；后续功能未定；不得自行添加钥匙、传感器、AI对手、登录、历史数据库；不得删减现有玩法；不得改用客户端判胜；不得为让代码“能跑”把隐藏玩家坐标广播给所有人。未知工程环境先检查，依赖版本需统一锁定。每次只交付一个可验证的小任务，说明改动、验证及未完成内容。

## 2. A：游戏逻辑任务书（用户）

所有成员和AI还需阅读[开源参考与复用方案](06_开源参考与复用方案.md)，完成各自OS-A/OS-B/OS-C阅读任务。生成或移植代码时附固定上游版本、原文件、采用方式和测试；不能把AI翻译上游代码写成独立原创。当前只确定优先研究Fugitive，尚未确定具体移植文件。

**职责目标：** 给B一个无需Android即可运行的权威规则引擎，给C/B一个安全完整的玩家视图。负责 game-core、game-data、规则测试；审核 contracts。

**现状（2026-10-24）：** contracts 的 DTO/接口、game-data 的加载与哈希、A1 的严格数据校验/可达性检查、game-core 的移动原型（固定步、碰撞、朝向、超时、中断）已存在；A2 的状态容器与正式引擎、A3 之后的光束、标记、物资、撤离都还没有。起点见 [08 骨架现状](08_骨架运行与交接.md)，不要重建已有工程。

按顺序实现：

1. A1：地图/规则数据模型、加载及合法性校验，测试地图，坐标与几何工具。验收为可达性、墙体射线和圆形碰撞单测。
2. A2：MatchEngineFactory、MatchInit、内部 MatchState、固定步移动、朝向、超时与唯一结果。提供B调用样例及测试输入序列。
3. A3：光束、标记、隐身/免疫、角色视野和 PlayerView；先证明警察视图不含私有字段再交接。
4. A4：物资状态、单件携带、交互候选/锁定/取消、丢弃与重新拾取、交付与出口。
5. A5：正常与异常结局优先级、结束幂等、新局重置；完整规则边界回归。
6. A6：正式地图设计与试玩修正，保留版本和hash；接口整合审阅。

**给AI的任务模板：**

> 我负责Light Chase的游戏逻辑。请先读取上述文档和现有工程，只在game-core、game-data及对应测试中实现本次任务【填写A1/A2等及具体功能】。契约由contracts共享，不复制DTO。不得让引擎依赖Android、libGDX、WebSocket或系统时钟。用整数逻辑步验证边界。共享接口不足时先给出具体差异，再协同更新，不在内部偷偷加网络字段。完成后给出运行命令、测试结果及给B/C的交接内容。

每次交接：引擎接口使用例、地图/规则版本、测试场景、PlayerView样例、仍未实现的规则清单。不要以“接口可调用”替代真实规则通过。

## 3. B：联网任务书

**职责目标：** 打通客户端输入到引擎及安全视图回传；负责 server、client-network、contracts维护和顶层构建协调。

**现状（2026-10-23）：** B1（contracts、Codec）与 B2（握手、资源哈希、房间、角色互斥、心跳、离开）已完成并有集成测试；B3 起（准备、倒计时、固定步调度、快照）未实现。不要重做 B1/B2。改准备流程会先撞 `LobbyIntegrationTest` 中 `setReady(true)` 返回 INVALID_PHASE 的断言（S0 的预期行为），需同步更新测试，并更新 [03 验收手册](03_联调与验收手册.md) 的完成度。

按顺序实现：

1. B1：与C确定并锁定构建工具；创建contracts DTO/枚举/接口和JSON Codec；编写合法/非法包测试。
2. B2：Java服务端启动、监听、会话、HELLO、资源一致性校验、JOIN_ROOM、房满和错误处理。
3. B3：角色互斥、准备、取消倒计时、房间状态机与revision；使用假引擎验证流程。
4. B4：固定步调度、命令队列、调用A引擎、分别发送A的viewFor输出；输入序号/dropId/租约。
5. B5：实现ClientGateway与GatewayListener，向C屏蔽JSON和网络库；连接超时、心跳、疑似/掉线、生命周期通知。
6. B6：GAME_OVER重复投递/确认、返回大厅、新局、旧局包拒绝、背压和限流；双模拟器完整集成。
7. B7：服务器打包、可配置端口、运行说明、诊断日志、协议示例与测试记录。

**给AI的任务模板：**

> 我负责Light Chase联网，经验较少。请按上述契约实施【填写B任务】，逐步解释入口、线程、消息和测试命令。只修改server、client-network、contracts及经协调的构建文件。玩法由game-core决定，不能在网络代码重新实现光照、交付或胜负。只传PlayerView，不序列化内部MatchState。先用假引擎/假客户端验证当前任务，再接真实引擎。任何字段变更同时更新文档、DTO、Codec、示例和测试，不用私有临时协议绕过缺失功能。

每次交接：ClientGateway可用方法、线程回调说明、服务器启动命令、端点和版本、协议实例、错误码、测试结果、已知缺陷。不能要求C自己实现第二套WebSocket连接。

## 4. C：Android界面与输入任务书

**职责目标：** 将合法PlayerView展示成可操作的Android游戏；负责 android、client-core、资源、FakeGateway与UI测试。

**现状（2026-10-23）：** C1 已完成（横屏壳、资源加载、世界视窗）；C2 只有离线演示大厅与对局占位，连接/倒计时/结算页面和 FakeGateway 的完整时序都没有；C3 起未开始。`AndroidLauncher` 目前硬编码 FakeGateway，真实网关注入点尚不存在。FakeGateway 的 `setReady(true)` 直接进 RUNNING 且不产生 onResult，C2 要按 [接口契约](02_接口契约.md) 的时序扩展它，不能把它当成已完成的对局替身。

按顺序实现：

1. C1：Android/libGDX工程壳、横屏、资源加载、统一世界视窗、不同屏幕留边；与B锁定构建。
2. C2：FakeGateway脚本和连接/大厅/倒计时/对局/结算页面；覆盖加载与错误状态，不等真实服务器。
3. C3：多点触摸摇杆、交互按住/释放、丢弃脉冲；切页与后台清空；只调用ClientGateway。
4. C4：地图、自身与可见敌人、被墙裁切的光束、小地图；敌人隐藏时清除全部表现和缓存。
5. C5：时间/标记/交付HUD、小偷携带/保护/交互进度、不可操作原因；警察无私有状态面板。
6. C6：替换真实网关、队列切回渲染线程、插值、网络状态提示、结算返回和新局清理。
7. C7：不同模拟器比例、触控和生命周期验证、APK打包；有真机时补触控/网络验证。

**给AI的任务模板：**

> 我负责Light Chase的Android展示与输入，经验较少。请读取上述文档，实施【填写C任务】，解释页面入口、事件回调和运行方法。只修改android、client-core及资源/对应测试；使用contracts.ClientGateway与PlayerView，先做FakeGateway。不得自己解析WebSocket或计算抓捕/交付/胜负，不得拿完整世界状态自行隐藏敌人。必须处理多指触摸、释放、切后台、网络断开和新局清理。完成后用相应视图场景验证，说明哪些只在模拟器验证、哪些真机待测。

每次交接：页面截图或录屏、模拟器配置、操作到InputFrame的说明、合法视图场景、真实网关注入位置、构建/运行命令。截图不能代替输入与生命周期测试。

## 5. 提交与联调的共同规则

每次任务交付附：任务ID、对应F/A/T编号、修改目录、构建命令、测试命令与实际结果、需要其他人配合的接口、未完成项。不能只给“已完成”三个字。

遇到接口冲突先以最小可复现消息或测试说明问题，三方修改同一份契约。B负责组织集成，不代表B承担A/C的业务修复。A作为规则负责人处理玩法歧义；C提出手感和UI问题，改变规则需回到A/B共同评审。

S0 已经通过：契约可编译、移动原型能推进一步、两连接能进房、假视图能展示并发出输入。S1 按 [03 验收手册](03_联调与验收手册.md) 的定义推进：A 给出无网络移动/碰撞/计时引擎，B 完成准备与倒计时，C 完成大厅/倒计时/结算页面与 FakeGateway 脚本。S1 的出口以 03 的表格为准，双方不可各自解释成“只要两连接进房”。


协作基线更新（2026-10-23，契约 R2）：开始独立开发前必须阅读接口契约第 12 节。GatewayListener 新增 onSession/onControl；A 按单步输入验收表实现规则，B 维护身份/控制请求和消息校验，C 将回调入队并按控制终态恢复按钮。共享变更应先合入共同基线，三人逐个可运行功能集成，不等所有模块写完才合并。当前仍是骨架，完整对局未实现。
