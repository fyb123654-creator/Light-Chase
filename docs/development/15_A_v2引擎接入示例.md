# A 部分 v2 引擎接入示例（给 B/C）

日期：2026-11-21；状态：A 侧已实现并通过 A 侧测试，B/C 尚未接入。字段定义仍以 [02 接口契约第 13 节](02_接口契约.md) 为唯一来源；本文只给接入顺序和容易踩错的边界。

## 1. 创建与推进

```java
import com.lightchase.contracts.MatchInit;
import com.lightchase.contracts.v2.*;
import com.lightchase.data.V2DataFiles;
import com.lightchase.game.V2EngineFactory;

V2DataFiles data = V2DataFiles.bundled();          // 24x18 测试扩展图
MatchInit init = new MatchInit(matchId, policeId, thiefId);
MatchEngine engine = new V2EngineFactory().create(data.map, data.rules, init);

// tick=0 的初始视图，B 可以直接发初始 SNAPSHOT
PlayerView police0 = engine.viewFor(policeId);
PlayerView thief0 = engine.viewFor(thiefId);

// 30Hz：第一拍 tick=1，之后严格 +1
StepResult step = engine.step(new StepInput(
        1,
        List.of(new PlayerCommand(policeId, 1, moveX, moveY, aimRad, held, dropId),
                new PlayerCommand(thiefId, 1, moveX, moveY, null, held, dropId)),
        List.of(),
        List.of()));
```

B 的服务端仍负责房间/倒计时/30Hz 调度；A 的 `step()` 只负责一拍规则。`Result` 为 `null` 表示对局继续；`step.ended()` 为 true 后，重复 `step` 返回固定结果、不推进 tick，也不会再次产生动作结果/事件。

## 2. B 侧输入映射

| C 的输入 | B 转给 A |
|---|---|
| `InputFrame.moveX/moveY` | `PlayerCommand.moveX/moveY`，最后一条命令生效 |
| `InputFrame.aimRad` | 警察原样传；小偷必须 `null` |
| `InputFrame.dropPressed` | B 生成单调 `dropId`，同一脉冲只分配一次；A 只消费大于上次的 ID |
| `ClientGateway.useItem(slot, expectedItemId)` | B 分配单调 `actionId`，生成 `PlayerAction(playerId, actionId, slot, expectedItemId)` |
| 持续输入 | 每拍可有多条 `PlayerCommand`，A 内部合并；B 不需要合并 |
| 离开/掉线 | `Departure(playerId, reason)` |

`serverTimeMs` 由 B 在把 A 的 `PlayerView` 放进 SNAPSHOT 前填写；A 返回 0。`ackInputSeq` A 已填该玩家已消费的最大输入序号，B 原样使用即可。

## 3. C 侧视图字段

| 字段 | 用法 |
|---|---|
| `self.aimRad/beam` | 仅警察非空；C 的画布光锥直接用 `beam.range`/`beam.halfAngleRad`，不要再用本地配置的旧范围 |
| `opponent` | 只有获准可见时非空；小偷看警察时含 aim/beam；警察看小偷时 aim/beam 为 null |
| `inventory` | 恰好 2 项，空槽为 `null`；只含本人库存 |
| `effects` | 只含本人效果；`untilTick` 是绝对截止，按 `tick` 换算剩余时间 |
| `interaction` | 顶层字段，两角色都有；`candidate/active/progressTicks/requiredTicks/requiresRelease/blockedReason` |
| `groundItems/groundCards` | 双方全图公开且未拾取；拾取后立即消失 |
| `portals` | 全部通道；`unlocked/revision` 决定灰色/启用色 |
| `transits` | 至多一条，双方相同；小偷 `self.motion=TRANSIT` 且 `self.x/y` 为光球位置；警察此时 `opponent=null` |
| `thief` | 仅小偷非空；含携带物资、保护截止、地面任务物资、已交付 ID、卡槽 |
| `remainingTicks/marks/deliveredCount/exitsOpen` | HUD 直接显示 |

C 不需要自己计算命中、拾取成功、护盾是否生效、通道是否解锁；这些只能以服务器视图/`ActionResult` 为准。

## 4. 动作结果

`StepResult.actionResults()` 只包含本拍处理的 `USE_ITEM` 结果，按 B 提交顺序：

```text
ActionResult = {matchId, actionId, slot, expectedItemId, success, code, appliedTick}
```

- 成功：`success=true`、`code=OK`，对应槽已在同拍清空；库存仍以 SNAPSHOT 为准。
- 失败：`success=false`、`code` 为 `EMPTY_SLOT` / `ITEM_INSTANCE_MISMATCH` / `ROLE_FORBIDDEN` / `IN_TRANSIT` / `EFFECT_ACTIVE` / `STALE_ACTION` / `MATCH_ENDED`，不消耗道具。
- 同一 `actionId` 重复提交且内容相同：A 返回缓存的原结果，不重复执行；缓存淘汰后的旧 ID 返回 `STALE_ACTION`。
- 动作结果只发给操作者；B 用 `matchId+playerId+actionId` 关联自己的 PENDING。
- 已结束的对局：`step` 返回空动作结果；B 负责把自己的待处理动作以 `MATCH_ENDED` 收尾。

## 5. 传送事件

成功进入通道的同拍，`StepResult.events()` 含一条：

```text
PublicEvent = {eventId=transitId, type=PORTAL_STARTED, matchId, tick, portalId, transitId}
```

B 给双方可靠有序发送一次；C 每局维护已提示 ID 集合。C 也可以从任意中途 `SNAPSHOT.transits` 恢复动画，不要求开始事件先到。光球位置由 A 的 `TransitView` 和 tick 决定，C 只做插值。

## 6. 固定接入检查清单

- [ ] 初始 `tick=0` 视图可以发出；第一拍 `visibilityChanged=true`。
- [ ] 警察 `aimRad` 独立；移动不改变手电方向。
- [ ] `INPUT` 的 `dropPressed` 只转一次 `dropId`；重复/旧 ID 不重复丢弃。
- [ ] `USE_ITEM` 的 `actionId` 单调；重复请求不消耗第二件同类道具。
- [ ] `inventory` 两个元素、空槽 `null`；`effects` 只含本人。
- [ ] `portals` 双方一致；通道入口才能解锁/进入，出口没有候选。
- [ ] 解锁后必须松开再按才进入；传送中 `self.motion=TRANSIT`，警察 `opponent=null`。
- [ ] 传送落地没有额外保护；下一拍才恢复移动/交互。
- [ ] 真隐身禁止全部交互；免疫仍可交互。
- [ ] 新局创建新的 A 引擎，不复用上一局引擎。

## 7. 最小验收脚本

A 的测试已经覆盖同一组场景；B/C 接入时可对照：

```powershell
.\gradlew.bat :game-core:test --tests "com.lightchase.game.V2*" --console=plain
```

重点看：

- `V2FullMatchTest`：三次交付 + 拾卡/解锁 + 传送 + 撤离整局。
- `V2TransitTest`：传送时间线、落地清输入、携物传送、传送中结束。
- `V2ShieldTest`：护盾 `max` 刷新、免疫原截止、EffectView。
- `V2WireCompatibilityTest`：A 的视图/事件/动作结果通过 B 的严格 codec。
