# 功能拓展：三人分工与联合调试

日期：2026-11-16。对应[组员版功能说明](../requirements/2026-11-16_组员版功能拓展说明.md)与[实现基线](../requirements/2026-11-16_功能扩展实现基线.md)。这是开发计划，不是已实现报告。2026-11-16 规则已由用户确认，字段以 [02 R3](02_接口契约.md) 为准；不再等待成员会议确认玩法。

本次修订加入：门禁卡必需且独立卡槽、护盾在已有保护期间按 max 刷新、双方右上角小地图及出入口灰色/启用色。以下任务全部包含这三项，不以开局全开通道或禁止重复护盾替代。

## 一、分工结论

**沿用 A 游戏逻辑、B 网络信息传递、C App 控件与 UI。可以并行开发，但必须先统一契约，再使用替身独立验证，最后按功能接通。**

| 成员 | 一句话职责 | 主要目录 |
|---|---|---|
| A：游戏逻辑 | 决定动作是否合法、什么时候生效、双方能看到什么 | game-core、game-data |
| B：网络信息传递 | 把操作可靠地送给规则引擎，把对应玩家的结果送回手机 | contracts、server、client-network |
| C：App 控件与 UI | 把触控和手机姿态转成操作，按服务器结果绘制和播放效果 | app、client-core |

A 不写网络收发，B 不另写道具或传送规则，C 不在 UI 中判定无敌、命中、拾取成功。继续使用同一多模块项目，不复制为三个独立工程。

## 二、开工前先完成共同接口

B 维护 `contracts` 和 `02_接口契约.md`，A 审核规则与可见性，C 审核输入和显示是否够用。下表作为功能概览；精确 API、完整字段和时序已经在 02 第 13 节定义。当前源码尚未迁移，不能把目标契约当作现有实现。

### 客户端需要发送的动作

| 动作 | 必要内容 | 处理约定 |
|---|---|---|
| 移动 | 移动方向 | 沿用原移动规则 |
| 独立瞄准 | 光照角度、是否有有效瞄准输入 | 弧度、坐标系、角度规范化方式与原工程一致；不把缺省角度误当成朝右 |
| 使用道具 | 槽位、期望道具实例 ID、唯一操作 ID | 实例 ID 防止旧请求消耗槽位内后来捡到的道具；操作 ID 防重复 |
| 拾取/进入传送门 | 沿用交互意图或共同约定的目标请求 | A 判距离、目标、状态；客户端不能宣称已经成功 |
| 拾取门禁卡/解锁通道 | 交互意图与目标 ID，独立动作的唯一操作 ID（如采用） | A 校验卡、角色、距离和通道；B 不接受客户端直接设置 unlocked |

陀螺仪开关和校准留在 C 的本地设置及输入层，不需要把原始传感器读数发给 B/A；校准后的瞄准角度通过相同入口发送。

### 服务器需要返回的状态

| 内容 | 用途与权限 |
|---|---|
| 自己的两槽道具实例 | C 绘制两个独立按钮；默认不发送对手背包 |
| 小偷独立门禁卡存储 | 空或一张卡（卡实例 ID、对应通道 ID）；只给小偷自己的视图，不复用道具/任务物资字段，警察不含私有卡槽 |
| 地面门禁卡 | 唯一 ID、对应通道 ID、位置及拾取状态，双方公开位置及拾取消失；不广播隐藏小偷坐标 |
| 公开通道定义与解锁状态 | 通道 ID、入口/出口、单向关系、是否解锁、状态修订；双方开局即可定位端点，后续按权威状态换色 |
| 地面道具 ID、类型、角色、位置 | 双方显示地图道具；双方全图公开未拾取道具，拾取后移除 |
| 自己的生效效果与截止 tick | 显示加速、光照强化、护盾剩余状态，避免只靠一次动画 |
| 移动朝向与警察光照朝向 | 不再用单个含糊的 heading 同时代表两种方向；共享类型中明确语义 |
| 有效光照参数 | C 光束长度、裁切与 A 实际照射使用一致参数；对手可见时亦需足够数据正确绘制 |
| 公开传送实例 | 唯一 ID、通道 ID、起点、终点、开始/结束 tick、传送角色；双方可见 |
| 传送提示标识 | 一次成功传送只提示一次；与公开传送实例 ID 关联 |
| 操作结果或失败原因 | 满槽、无道具、效果已生效、非法角色等；不能用本地猜测更新库存 |

小地图不需要另发全量真实世界状态：静态布局来自同版本地图文件，动态对象沿用 A 过滤后的角色视图，公开通道和传送效果按明确例外发送。不能因为小地图而新增“所有玩家坐标”接口。

B 与 A 共同定义“动作失败”的反馈路径，不能为了开发方便让规则引擎直接操作 socket。共享数据均保持无 Android/libGDX 依赖。

### 已确认规则与共享实现

用户已采纳决策表 E01–E12：两通道四端点、按住拾取/解锁、释放重按才进入、本局永久解锁、不能丢卡、可携物传送、真隐身禁止全部交互、免疫原截止不延后、加速/光照禁止同类重复、地面道具/卡全图公开。瞄准和校准规则同样已确认。

新增字段、失败码、顶层 interaction、期望卡实例锁定、USE_ITEM/ACTION_RESULT/PUBLIC_EVENT、去重和单步顺序均采用 02 R3；不用另起私有协议。B 的第一项是将文档目标落实为公共类型/Codec 和共同提交，A/C 审阅与适配，不再各自决定规则。

## 三、A：游戏逻辑任务

| 编号 | 工作 | 交付内容 |
|---|---|---|
| A1 | 警察移动与光照方向分离 | 服务端独立照射角度；移动不覆盖已指定的瞄准 |
| A2 | 两槽库存、拾取、使用 | 两槽独立实例；同类可共存；满槽保留地面道具；重复请求不重复消耗 |
| A3 | 光照和加速效果 | 按配置和 tick 生效/结束；真实判定变化，结束恢复 |
| A4 | 护盾 | 清零 beamProgress、按 max 刷新剩余真隐身；INVISIBLE/IMMUNE 时也消耗，不改变 marks、不触发成功标记事件 |
| A5 | 单向传送 | 角色/入口/已解锁校验、起止 tick、落点、无冷却、过程状态和清理 |
| A6 | 地图与权限投影 | 道具、门禁卡及有向通道配置校验；公开解锁与光球、私有卡槽、落地恢复过滤 |
| A7 | 可重现的规则验收 | 纯 JVM 脚本/测试驱动上述功能；新局清理与原胜负流程回归 |
| A8 | 门禁卡与解锁 | 一卡对应一通道、单张独立卡槽、持卡拒绝拾取、匹配成功销毁并解锁、失败不扣卡、重复请求安全、新局恢复 |
| A9 | 小地图所需权限 | 给出全体公开静态通道、动态状态和各角色可见对象；隐身小偷不进入警察普通对象列表 |

A 不必等真实手机：通过统一动作创建引擎、推进 tick、检查 PlayerView 即可。传送的权威状态来自 A，光球美术和插值来自 C。

### A 的详细工作顺序与交接

1. 整理现有移动、照射、保护和交互流程，按 02 R3 核对新增字段，尤其分离行进方向与光照方向。
2. 先实现两槽和固定地面道具；给每件地面/背包道具稳定实例 ID。接入加速、光照，再接入护盾刷新。
3. 护盾使用先取原剩余真隐身，再清照射进度并更新截止，保证同一步的新照射不会先完成标记；终局不能被道具复活。
4. 新增地面门禁卡、单张独立卡槽和通道锁定状态。按卡 ID 与通道 ID 一一匹配；道具满槽不阻止拾卡，但已有卡时拒绝拾其他卡并保留地面卡。成功解锁与销毁卡、清空槽在同一步完成；失败不扣卡，重复请求不扣新卡或触发传送。A 只负责逻辑对应，不设计颜色。
5. 在已解锁通道上接入单向传送，公开光球与隐藏角色分开投影；墙体不阻挡光球直线动画。
6. 提供测试地图、参数与视图样例，检查无卡时无法解锁、不可达卡点/非法落点及新局重置。
7. 提交边界用例：真隐身剩余大于/小于/等于道具时长，免疫中使用，两件护盾依次使用；标记次数始终不因护盾改变。

A 交给 B/C 的结果：可调用引擎、配置格式、每个动作的预期结果、按角色过滤的样例；不要求他们猜测保护时间和可见性。

## 四、B：网络任务

| 编号 | 工作 | 交付内容 |
|---|---|---|
| B1 | 契约与版本 | 类型、字段语义、样例、失败反馈和协议升级 |
| B2 | 新动作传递 | gateway → WebSocket → 房间队列 → 引擎；移动与瞄准并行，离散动作不丢失 |
| B3 | 状态回传 | 两槽、卡槽、地面卡、通道状态、效果、光照和光球正确编码解码；只序列化 A 为该玩家生成的视图 |
| B4 | 重复和过期防护 | 使用道具操作去重、实例匹配、错误槽位/角度/类型拒绝；不信任客户端提交的效果或位置 |
| B5 | 传送同步 | 两端使用相同传送 ID、起止时间；提示去重；客户端晚收到活动快照仍能显示剩余过程 |
| B6 | 独立联网验证 | 假引擎＋两个 JVM 客户端验证流程、版本不符、重复消息、新局及断开 |
| B7 | 解锁与小地图同步 | 两端相同通道修订；丢过一次提示后仍能从快照恢复颜色；小地图不获得完整隐藏角色状态 |

B 不负责读取陀螺仪，只接收角度。网络层拒绝坏消息，玩法层判断动作当前是否合法，两者不重复实现。

### B 的详细工作顺序与交接

1. 按 02 R3 落实字段表和样例，先合入共同 contracts 基线，再让三方引用，不让两人等待网络完成。
2. 升级协议版本和严格结构校验，同时更新输入到 PlayerCommand、规则视图到网络快照的每一层映射，避免新增字段在中途被遗漏。
3. 区分持续输入（移动/瞄准）与一次性操作（用道具/解锁）；绑定当前会话玩家身份，拒绝伪造别人操作。
4. 验证实例 ID、操作 ID 和 matchId 的去重/过期处理，防止迟到的护盾请求消耗新槽物品、旧解锁请求消耗后来拾取的新卡、上一局解锁影响新局。传递卡与目标通道的稳定 ID，不传颜色来判断匹配。
5. 每份正常快照都能表达当前库存、保护截止、通道状态和活动传送；音效只按唯一事件提示，不能每帧重放。
6. 用假引擎生成两种角色视图，验证卡槽只到小偷、双方收到相同公开通道与光球、隐藏小偷坐标不到警察端。
7. 给 C 可运行服务器与测试连接方式，组织每个功能的双端调试，记录真实设备尚未完成项。

B 交给 A/C 的结果：正式契约、共享样例、可用的 gateway/服务端、错误反馈说明与双客户端测试记录。

## 五、C：App 控件和 UI 任务

| 编号 | 工作 | 交付内容 |
|---|---|---|
| C1 | 双槽 UI | 两个道具按钮、相同图标也独立显示和点击、空槽状态、效果提示；不覆盖原交互/丢弃控件 |
| C2 | 地图显示 | 道具、门禁卡、传送入口/出口及方向；灰色锁定/启用色解锁；拾取、缺卡和满槽反馈 |
| C3 | 触控独立瞄准 | 左移动、右瞄准，多点触控同时有效；只提交角度意图 |
| C4 | 陀螺仪及设置 | 游戏外开关和设备检测；开启后右侧仅校准按钮，关闭后仅瞄准摇杆 |
| C5 | 校准与生命周期 | 当前方向对齐、静止/未移动默认、相对姿态基准、平滑、后台停止采样 |
| C6 | 传送表现 | 双方可见的直线光球、隐藏普通人物、按权威进度播放、小地图显示、落地清插值 |
| C7 | 视听与替身演示 | 每次传送一条提示/音效、道具与保护视觉反馈；假网关展示所有新状态 |
| C8 | 独立卡槽 UI | 小偷单张卡区域、空/持有状态、已有卡不能拾取提示；设计卡与通道对应的颜色/符号，按权威状态更新 |
| C9 | 右上角小地图 | 复用现有 Minimap 并迁移；全地图按比例显示、自身红点、公开通道灰色/启用色、可见对象和光球 |

C 维护客户端假网关；它只提供稳定样例来做页面和输入开发，不另造一套正式规则。真实引擎离线模式仍复用 A 的实现。

### C 的详细工作顺序与交接

1. 先画一张对局布局草图：右上角小地图、两道具槽、小偷独立卡槽、左移动和右瞄准/校准；避开原有右上退出按钮和计时，必要时挪动退出入口但保留功能。
2. 扩展现有 `Minimap`，不创建另一套全图状态。使用地图宽高统一缩放，正确处理长宽比、屏幕适配和左下世界坐标到 UI 坐标的转换。
3. 自身位置用红点；对手用不同图形/颜色且只在允许可见时显示。公开通道带入口/出口方向标识，灰色锁定、启用色解锁，不靠颜色作为唯一标识。
4. 在小偷 UI 独立显示单张门禁卡，不挤占两道具槽；设计卡与对应通道的颜色、符号等视觉标识，逻辑仍依赖 ID。已有卡时给出不能再拾卡的提示；拾取/解锁只提交意图，收到状态后才清空卡槽、换通道颜色，不本地提前销毁卡。
5. 护盾期间按钮不因为“已经保护中”而自动禁用；第二件可继续提交使用。剩余时间按服务端新截止显示，不在本地累加。
6. 传送中主画面隐藏普通人物，显示直线光球；双方小地图显示同一光球，小偷自己的红点跟随其进度；落地清理光球和旧插值，隐藏对手点立即移除。
7. 实现双摇杆，再接入陀螺仪和校准互斥模式；传感器原始值留在本地，设置不支持检测与后台清理。
8. 用假网关覆盖全部新状态，再接真实 gateway 验证。提交截图/录屏、操作说明和真机型号及结果。

C 交给 A/B 的结果：可运行界面、输入映射、假网关场景和显示问题清单；不在 UI 中另算拾卡成功、护盾刷新或通道解锁。

## 六、怎样独立开发

| 成员 | 不依赖什么 | 用什么替代 | 独立通过标准 |
|---|---|---|---|
| A | 手机、网络 | 脚本动作和固定 tick | 指定输入得到指定状态和角色视图 |
| B | 新规则和 App | 实现现有引擎接口的假引擎、两个 JVM 客户端 | 请求正确入队、状态正确到达、非法和重复请求正确处理 |
| C | 真实服务器、新规则 | ClientGateway 假网关、共享快照样例 | 输入正确生成、布局可操作、所有状态显示正确 |

B 维护共享样例文件，A 提供预期规则结果，C 确认能直接驱动 UI。至少包含：同类双槽、满槽但可拾卡、私有卡槽、通道灰色锁定/解锁、护盾首次与保护中再次使用、移动与瞄准方向不同、公开光球传送中/结束、对手可见/隐藏的小地图状态。样例不含真实传感器读数。

共享接口先合入共同基线，各自在各自模块开发。contracts 或地图格式后续有变化先通知三方，不能长期保留三套不兼容类型。

## 七、联合调试顺序

每一阶段都走 A 规则 → B 真实网络 → C 真实页面，不等三人全部完成再首次连接。

| 阶段 | 联调内容 | 通过证据 |
|---|---|---|
| J0 | 共用新契约、协议版本和测试地图配置 | 三方编译通过，样例编解码通过，不兼容版本被拒绝 |
| J1 | 左右摇杆独立移动/瞄准 | 两端实际照射结果与画面一致，移动不覆盖光照方向 |
| J2 | 双槽、拾取、使用和基础效果 | 满槽拒绝、两件同类独立消耗、加速和光照真实生效 |
| J3 | 护盾 | 累计照射被清空、marks 不变；真隐身/免疫中可消耗，max 刷新不叠加、不缩短；结束恢复 |
| J4a | 卡槽与解锁 | 满道具槽仍可拾卡；持卡拒绝拾其他卡且地面卡保留；无卡/警察/错卡解锁失败不消耗；匹配成功销毁卡清空槽；重复请求不扣后拾新卡；两端地图同步换色 |
| J4b | 单向传送与公开光球 | 未解锁拒绝；警察拒绝、出口不可反进、无额外冷却、双方同轨迹和提示、落地无泄露 |
| J4c | 右上角小地图 | 两端自身红点正确，完整地图缩放正确，公开端点和光球可见；对手丢失可见性立刻去点，布局不挡操作 |
| J5 | 陀螺仪真机 | 游戏外切换、两种右侧控件、校准、设备不支持和生命周期处理 |
| J6 | 一局完整回归及重开 | 原胜负路径有效；新局库存、卡槽、地面卡、灰色锁定、效果、传送、小地图动态点及姿态全部重置 |
