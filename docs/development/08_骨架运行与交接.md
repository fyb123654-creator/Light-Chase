# S0 骨架运行与三人交接

日期：2026-10-23。本文记录已经存在的工程；需求及接口文档仍描述最终 V1 目标，不能把目标当成已完成功能。

## 1. 当前能运行什么

| 模块 | 当前实现 | 尚待实现 |
|---|---|---|
| contracts | 公共 DTO、枚举、输入验证、引擎/网关接口及基础几何 | 随联调补齐边界验证；不能私自改字段 |
| game-data | 从资源加载测试地图/规则、按原始字节计算 SHA-256 | 正式关卡、完整数据合法性及可达性验证 |
| game-core | PrototypeEngineFactory 创建移动原型；30Hz 固定步、碰撞、朝向、超时、中断 | 光束/遮挡、标记与保护、物资/交互、退出判负、最终角色权限 |
| server | Java-WebSocket 大厅、握手/哈希、房间、角色互斥、心跳、离开 | 准备/倒计时、房间逻辑线程、输入租约、快照、结果确认及重开 |
| client-network | 实际 WebSocket 网关、JSON 包络、连接/大厅回调、心跳及输入采样缓存 | 完整控制超时、严格各类 body 校验、完整结果/重开联调及有界队列 |
| client-core | libGDX 地图和占位角色、触摸摇杆/按钮、离线 FakeGateway | 正式大厅/对局/HUD/结算、插值、可见性表现、美术与中文字体 |
| android | 横屏启动、生命周期入口、网络权限声明、debug 明文配置 | API 37 局域网运行时授权、真实连接设置与真机兼容性 |

重要约束：

- AndroidLauncher 注入 FakeGateway；现有页面使用 offline 主机占位。不能仅替换构造函数就宣称 Android 联机完成，还要实现连接表单、权限、连接状态和真实准备流程。
- FakeGateway 是 C 的界面替身。START DEMO 只进入本地展示，角色移动不做玩法碰撞，HOLD/DROP 只采样操作，没有完成物资流程。
- MovementPrototypeEngine 不支持交互、丢弃及 Departure；遇到这些操作明确抛出 UnsupportedOperationException。B 接引擎前必须和 A 约定支持范围，不能吞异常继续假装对局有效。
- 原型的 opponent 始终为 null，警察没有 thief 私有数据；这是避免暴露信息的保守占位，不代表可见性算法已完成。
- 服务器 SET_READY(true) 返回 INVALID_PHASE 并提示 S0 尚未实现开始。集成测试的“两客户端”是 JVM WebSocket 客户端，不是两台 Android。
- 现阶段 server 依赖 client-network 复用 WireCodec；两者都由 B 维护、无 Android 依赖。若未来拆 protocol-codec 模块，先更新依赖图与契约，避免各自复制协议代码。

## 3. 首次拉取与运行

在 PowerShell 执行：

```powershell
git clone https://github.com/fyb123654-creator/Light-Chase.git C:\dev\Light-Chase
cd C:\dev\Light-Chase
.\gradlew.bat checkJvm :android:assembleDebug :server:installDist
```

`main` 与 `bootstrap` 现在指向同一提交，默认克隆即可，不需要再切分支。只跑 `checkJvm` 不依赖 Android SDK；构建 `:android:` 时需要，Android Studio 会写 `local.properties`，纯命令行可设 `$env:ANDROID_HOME="C:\Users\<你>\AppData\Local\Android\Sdk"`（2026-10-23 用全新克隆验证过这两种情况）。第一次下载可能较久；不要更换成来源不明的 Wrapper 或随意升级版本。

运行服务器：

```powershell
.\gradlew.bat :server:run
```

默认监听 0.0.0.0:8080，WebSocket 路径 /game，仅用于开发局域网。命令行 Ctrl+C 停止。也可运行 server/build/install/server/bin/server.bat；该目录及其 lib、许可证文件需要一起分发。

在第二个终端运行：

```powershell
.\gradlew.bat :server:probe --args="127.0.0.1 8080"
```

应输出 PASS: joined PROBE 及“只验证传输/大厅”的说明。端口占用时修改服务器启动参数并让探针对应一致：

```powershell
.\gradlew.bat :server:run --args="8081"
.\gradlew.bat :server:probe --args="127.0.0.1 8081"
```

运行 Android：Android Studio 选择 android 配置及模拟器，点击 Run。APK 位于 android/build/outputs/apk/debug/android-debug.apk。当前只包含 arm64-v8a 和 x86_64 原生库；32 位设备不在本轮构建范围。点击 THIEF/POLICE、START DEMO，拖摇杆观察坐标；松手应停止，BACK TO LOBBY 返回展示大厅。

未来真实联网地址：Android 官方模拟器到宿主机通常使用 10.0.2.2；真机使用电脑局域网 IPv4，不能填手机自身的 127.0.0.1。两设备同网，确认 Windows 私有网络防火墙允许 Java/开发端口，不能靠关闭防火墙解决。宿舍无线隔离时另选可互访测试网络。

targetSdk 37 下，ACCESS_LOCAL_NETWORK 已声明但还未申请运行时权限。C 在首次真实 LAN 连接前完成授权和拒绝反馈；B 不把权限失败误报成服务器宕机。debug 允许 ws 明文；release 没有开放明文，当前不是可发布版本。

## 4. 三人实际开工顺序

### A：规则实现

入口 game-core/src/main/java/com/lightchase/game/PrototypeEngineFactory.java、MovementPrototypeEngine.java；先读 MatchEngine、StepInput、PlayerView。保留已有移动测试，按需求顺序实现光束与墙体遮挡、标记累计/保护、物资闭环、超时和离开优先级。不得从 Android 或网络读取时钟；step 的 tick 来自 B。

每次交付注明已支持的输入、暂不支持的分支、新增测试和可复现样例。正式引擎准备好后再替换 Factory；不要把 FakeGateway 的移动展示当作权威逻辑复制。

### B：双端网络

入口 server/LobbyServer.java、ServerMain.java 和 client-network/WebSocketClientGateway.java、WireCodec.java。先保持现有握手/房间测试通过，再完成两人准备→倒计时→创建引擎。服务器统一固定步消费输入，每玩家独立调用 viewFor；禁止广播完整内部状态。注意两点：`LobbyIntegrationTest` 现在断言 `setReady(true)` 返回 INVALID_PHASE，实现准备流程时必须同步改这条测试；`SERVER_BUSY` 与 `BAD_MESSAGE` 的 fatal 标志目前与契约不一致（契约见 02 第 9 节），实现 B3 时一并修正。

随后实现输入租约、丢弃去重、逐角色快照、掉线/切后台 Departure、结果确认与重开。客户端网关对 C 暴露同一个 ClientGateway，所有 JSON 和线程调度留在网络层。增加双客户端测试后，再与 C 用两台模拟器联调。

### C：界面与 Android

入口 android/AndroidLauncher.java、client-core/LightChaseApp.java、FakeGateway.java。先在替身上实现服务器地址/房间表单、大厅状态、错误反馈、按钮禁用状态。将网络回调入队到渲染线程，触摸输入必须支持松手/取消/切后台归零；不得直接改规则模型。

真实连接作为明确可选模式注入 WebSocketClientGateway，保留离线演示便于独立工作。加入权限请求后和 B 验证两台模拟器大厅，再接权威快照。中文字体、美术、正式 HUD 后续逐项替换当前英文占位 UI。

客户端读地图/规则时，用 `Gdx.files.internal("maps/test-room.json")` 取字节后调用 `DataFiles.read(mapBytes, configBytes)`（`game-data` 已是 `client-core` 的依赖）。`DataFiles.bundled()` 只验证过 JVM classpath，不要假定在 Android 上同样可用；如果要用，先在模拟器实测再写进代码。哈希必须与服务器同源同字节，不能客户端自己重排 JSON。

### 集成顺序

1. 三人先在自己电脑成功执行 checkJvm 和 assembleDebug，记录环境差异。
2. B+C 打通真实 Android 大厅，A 并行开发规则；此时不要承诺完整一局。
3. A+B 接固定步引擎，C 接权威位置和视图；通过移动/断线用例。
4. 补齐追捕、物资、撤离及异常路径，按联调手册逐项验收 V1。

## 5. 分支、提交与 AI 协作

骨架分支 `bootstrap` 已于 2026-10-23 合并进 `main`，两者指向同一提交（`main` 是默认分支，克隆即可）。每位成员从最新 `main` 创建自己的功能分支，例如 `feat/rules-visibility`、`feat/network-countdown`、`feat/android-lobby`。合入前先拉取最新 `main`、解决冲突并运行受影响测试；不要三人直接在同一个远程分支推送。

提交作者由每个人本机 git user.name/user.email 决定，推送权限由登录账号决定。当前机器已有作者 Joker <2493895090@qq.com>，未修改全局配置。是否链接到 GitHub 个人主页取决于该邮箱是否属于对应账号；其他同学应在自己的克隆中配置自己的身份。

```powershell
git config user.name "自己的名字"
git config user.email "自己 GitHub 已验证的邮箱或 noreply 邮箱"
git switch -c feat/自己的任务
git status
git add 具体修改的文件
git commit -m "描述本次完成的功能"
git push -u origin HEAD
```

邀请另外两人为仓库协作者后，他们可推送各自分支；账号密码和访问令牌不要发到群或交给 AI。共享仓库链接和文档链接即可，不用来回传整个代码文件夹。

给 AI 的任务至少包括：本模块负责人、具体需求 ID、接口契约、08 当前限制、禁止修改范围、验收命令。禁止 AI 看到 FakeGateway 就声称联网完成，或为了让测试过而改掉已确认玩法。变更 contracts、地图字节、规则参数时通知另外两人；两端哈希必须相同。
