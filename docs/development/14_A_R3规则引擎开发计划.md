# A 部分 R3 规则引擎开发计划（v2）

日期：2026-11-21；负责人：A（游戏逻辑）；状态：A7–A12 已一次性实现并完成 A 侧验证，改动留在工作区，尚未提交 Git。

本文件只覆盖 A 的部分：`game-core` 的 v2 规则引擎，以及 `game-core` 内的 v2 配置校验。B 的网关/服务端和 C 的 Android 界面不在本计划内；A 交付的边界仍是 02 第 13 节定义的 `StepInput` → `StepResult` / `PlayerView`。

## 0. 先确认的范围

### 0.1 本轮已确认的设计

| 项目 | 结论 | 对 A 的影响 |
|---|---|---|
| 暗道 | 沿用 R3：小偷专用、两条单向通道、四端点、门禁卡解锁、传送中公开光球 | 规则按 02 §13.5–13.7 实现，不改玩法 |
| 道具 | 沿用 R3：双方各两槽；警察加速/光照，小偷加速/护盾 | 按 02 §13.6 实现 |
| 瞄准 | 去掉陀螺仪；C 使用“按住 AIM 按钮拖动瞄准”，松手保持方向 | A 只接收 `InputFrame.aimRad` / `PlayerCommand.aimRad`；不实现按钮、传感器或校准 |
| 协议 | 运行端最终切到 v2；v1 规则引擎和 v1 测试保留不动 | A 新增 v2 入口，不替换 `V1EngineFactory` |

### 0.2 本轮不做什么

- 不修改 `app/`、`client-core/`：AIM 按钮、道具槽、卡槽、小地图、光球渲染都是 C 的工作。
- 不修改 `server/`、`client-network/`：`USE_ITEM` / `ACTION_RESULT` / `PUBLIC_EVENT` 的收发、去重缓存和 v2 握手是 B 的工作。
- 不改 `contracts/v2` 的字段含义；发现缺口先记录、和 B 确认后再改，不私自加字段。
- 不做正式地图调平衡、随机生成、传送冷却、陀螺仪；这些不属于本轮 A 的范围。

| 项目 | v1 现状 | v2 目标 |

## 2. 规则口径

精确字段和时序以 [02 接口契约第 13 节](02_接口契约.md) 为唯一来源。实现时以下面这张表作为自检清单，不另写一套规则。

| 事项 | 口径 |
|---|---|
| 拍 | 第一拍 `tick=1`；`tick` 必须严格连续；引擎不读系统时钟、不用随机数 |
| 警察瞄准 | `aimRad` 非空才更新；首次取出生朝向；移动只改 `headingRad`，不改 `aimRad`；输出角度在 `[0,2π)` |
| 小偷瞄准 | `aimRad` 必须为 null；移动仍更新 `headingRad` |
| 移动 | 最后一条命令决定方向；整拍只移动一次；斜向归一化；加速只改有效速度 |
| 道具 | 两槽独立实例；同类可占两槽；满槽保留地面道具；成功使用只清对应槽 |
| 使用失败顺序 | 已结束 → 空槽/实例不符 → 角色 → 传送中 → 同类效果已生效 |
| 加速/光照 | 可并存；同类型有效期间拒绝再次使用且不扣槽；到期后可再用 |
| 护盾 | 清 `beamProgress`、不增减 marks、取消当前交互；`invisibleUntil=max(k+shieldTicks, 原截止)`；免疫截止不动 |
| 保护判定 | 先判真隐身，再判免疫；护盾结束后只接尚未到期的免疫，不自动新增免疫 |
| 拾取 | 靠近且静止按住；候选过滤后按距离升序、同距按 `targetId` 字典序；完成后必须松手重按 |
| 解锁/进入 | 两段交互；解锁成功才扣卡、开门、`revision=1`；入口交互，出口无候选；单向 |
| 传送 | `startTick..endTick-1` 禁移动/交互/用道具/再次进入；不参与地表照射；效果和计时继续；落地无额外保护 |
| 光球 | 公开数据；双方看到同一 `TransitView`；警察普通 `opponent=null`；落地立即恢复权限过滤 |
| 事件 | 起步发一次 `PORTAL_STARTED`，`eventId=transitId`；结算步丢弃未发布事件 |
| 视图权限 | 警察 `thief=null`；地面道具/卡公开；库存、卡槽、保护截止只给本人/小偷；隐藏小偷坐标不得出现在警察视图 |
| 结局 | 超时 > 第三次标记 > 撤离；正常结局 > 退出/掉线；双方同拍离开 `BOTH_LEFT`；结果只生成一次 |
| 新局 | 清库存、效果、卡、交互锁、通道、光球、动作去重、旧输入和插值；重新生成固定地面道具/卡 |

## 3. 代码结构

新增文件全部在 `game-core/src/main/java/com/lightchase/game/`，类名统一带 `V2` 前缀，避免和 v1 状态混用：

| 文件 | 作用 |
|---|---|
| `V2EngineFactory.java` | 唯一公开入口，实现 `contracts.v2.MatchEngineFactory`；构造前校验规则/地图 |
| `V2MatchEngine.java` | 实现 `contracts.v2.MatchEngine`；单步入口、幂等、abort |
| `V2MatchState.java` | 整局可变状态：演员、物资、道具、卡、通道、传送、动作缓存 |
| `V2ActorState.java` | 单个演员：位置、朝向、瞄准、输入记忆、库存、效果、交互 |
| `V2InputMerger.java` | 同拍命令合并：移动/瞄准/按住边沿/dropId；动作列表单独保留 |
| `V2InteractionState.java` | 每角色候选/锁定目标/进度/是否要求松手/阻塞原因 |
| `V2ViewProjector.java` | 生成两份不可变、按角色过滤的 `PlayerView` |
| `V2RuleMath.java` | 角度归一化到 `[0,2π)`、半角、矩形视野 |
| `V2ConfigValidator.java` | 规则参数和地图结构校验；不依赖 Android/网络 |

可以复用 v1 的 `RuleMath` 中不变的数学、`WorldGeometry` 的碰撞/遮挡、基础 `MatchResult`/`MatchInit` 类型；但 v1 的 `MatchState` 和 `ViewProjector` 不改，避免把 v2 字段塞进 v1 视图。

测试文件放在 `game-core/src/test/java/com/lightchase/game/`，统一用 `V2` 前缀；共享测试地图/规则放在 `V2TestData.java`，不修改正式 `extension-v2.json` 字节。

### A7 v2 骨架、独立瞄准与视图基线

**目标：** B 能创建 v2 引擎，推进空对局，拿到合法的双方视图；警察移动和瞄准已经分离。

**实现：**

- `V2EngineFactory` + `V2MatchEngine` + `V2MatchState` + `V2ActorState` 骨架。
- 构造校验：规则全参数、出生点、地图 `mapVersion=2`、双方 ID 不同、拍率 30。
- 同拍输入合并：最后一条移动命令生效；`aimRad` 非空才更新；按下/释放边沿；dropId 单调。
- 移动、朝向、警察光束、超时、退出、`abort`、结束后幂等。
- 基础 `PlayerView`：`self`/`opponent` 的空视图、`remainingTicks`、`ackInputSeq`、`serverTimeMs=0`。
- `V2ViewProjector` 先只投影移动/瞄准/超时，不含道具/通道。

**测试：** 工厂拒绝非法规则/地图；首拍与连续拍；不连续 tick 抛错；斜向不加速；撞墙滑动；移动不改 `aimRad`；`aimRad=null` 保持上次；警察 `beam` 非空、小偷 `aimRad/beam=null`；超时/退出/双方离开；abort/幂等；结束后的视图不含可开始交互。

**验收：** `:game-core:test` 中 `V2*` 全过；B 可以用 `new V2EngineFactory().create(V2DataFiles.bundled().map, ...rules..., init)` 创建引擎并连续 step。

### A8 双道具槽、拾取与加速/光照

**目标：** 双方各有两槽；能拾自己的道具、分别使用、效果真实生效并到期恢复。

**实现：**

- 地面道具 `itemId → GroundItem`；拾取后删除地图实例，放入最低索引空槽。
- 两槽独立 `ItemInstance`；同类可占两槽；满槽拒绝且地面保留。
- 使用动作：`PlayerAction`（actionId/slot/expectedItemId）→ `ActionResult`；每玩家最高 ID + 有限缓存去重；失败码精确使用 02 §13.3。
- 加速：有效速度乘 `speedBoostMultiplier`；光照：有效 `beamRange` 乘 `lightBoostMultiplier`；`BeamView` 输出实际参数。
- 效果截止 `untilTick`；同类有效期间 `EFFECT_ACTIVE` 且不扣槽；加速/光照可并存。
- 警方/小偷的 `interaction` 顶层化；警方只能拾 `ownerRole=POLICE` 的道具，不能拾卡/解锁/进入；小偷可拾自己的道具。
- 拾取必须静止按住；移动/松手/被标记取消；完成后要求松手重按。

**测试：** 两件同类各占一槽；槽满不拾；指定槽使用不误扣另一槽；实例 ID 不匹配不扣；旧 actionId 不会消耗新道具；重复 actionId 返回原结果；角色不符；传送中拒绝；加速/光照真实改变移动距离/视图光束；到期恢复；效果并存；警方不能拾小偷道具；拾取失败码；拾取取消条件。

**验收：** 用 `extension-v2.json` 的道具点跑固定脚本；`BeamView.range` 与规则倍率一致；`inventory` 恰好两个元素，空槽为 null。

### A9 护盾与保护截止

**目标：** 护盾清照射进度、刷新真隐身 `max`、不改变 marks/免疫原截止。

**实现：**

- `invisibleUntilTick` 与 `markImmuneUntilTick` 独立存储；保护状态派生，不在每步把两个截止混在一起清空。
- 护盾：只允许小偷；清 `beamProgress`；取消当前交互；`invisibleUntil=max(now+shieldTicks, 原 invisibleUntil)`；`markImmuneUntil` 不变；成功消耗对应槽。
- 真隐身期间禁止全部交互（任务、道具、卡、解锁、进入），允许移动和使用已有道具；免疫可正常交互。
- `EffectView`：SHIELD 只在本次护盾已使用且真隐身尚未结束时出现，`untilTick` 与合并后的 `invisibleUntilTick` 一致。
- 同一步顺序：道具先于移动/照射；护盾先清进度，再处理该步照射；第三次标记先于交互完成。

**测试：** 护盾清进度但 marks 不变；剩余真隐身大于/小于/等于道具时长三种；两次护盾依次用；免疫期间使用；原免疫截止不延后；真隐身禁止全部交互；免疫可交付；护盾取消交互；同拍护盾+照射；终局后不能靠护盾复活；新局清空效果。

**验收：** 复现 02 §13.6 的两个示例；`protectionRemainingTicks` 与 `untilTick` 边界正确；`marks` 只由成功照射改变。

### A10 门禁卡与解锁

**目标：** 小偷拾卡、独立卡槽、匹配解锁；警察不能参与；解锁状态双方公开。

**实现：**

- 地面卡公开列表；小偷靠近静止按住拾取；警察不能拾卡/解锁。
- 小偷独立 `card`（最多一张）；已有卡时拒绝拾其他卡且地面卡保留；卡不能丢弃/替换。
- `UNLOCK_PORTAL` 只能在入口交互；`expectedCardId` 在开始时锁定；完成时再次校验卡仍在、卡与通道匹配。
- 成功：`unlocked=true`、`revision=1`、销毁卡、`card=null`；失败不消耗。
- 重复/迟到请求不能扣后来拾到的另一张卡；已解锁不再提供 `UNLOCK_PORTAL` 候选。
- `portals` 在双方视图中始终包含全部通道；卡槽只在 `thief` 私有视图。

**测试：** 拾卡成功/卡槽已满；警察不能拾卡；满道具槽不影响拾卡；错卡解锁失败且不扣；正确解锁扣卡/开门/revision；重复解锁不扣新卡；解锁后必须松开重按才能进入；新局卡/门恢复；视图权限。

**验收：** 用 `extension-v2.json` 的 C1/P1、C2/P2 配对；双方 `portals` 一致，警察视图无 `thief.card`。

### A11 单向传送、公开光球与落地

**目标：** 解锁后小偷独立完成进入交互，传送过程公开可见且不泄露落点。

**实现：**

- `ENTER_PORTAL` 仅小偷、已解锁、入口、非传送中；完成时创建唯一 `transitId`，`startTick=当前 tick`、`endTick=start+transitTicks`。
- 起步：普通角色从地表隐藏；`PublicEvent` 一条；`transits` 双方一致；小偷 `self.motion=TRANSIT`、位置按进度插值；警察 `opponent=null`。
- 传送中：禁移动、交互、道具、再次进入；不参与地表照射；效果和计时继续；输入缓存可更新但不产生移动/交互。
- 到达步：清旧移动/按住（含本步旧输入）、本步不移动不启动交互、设 `requiresRelease`；落到出口、恢复地表规则、无额外保护/冷却。
- 传送中不重复接收进入；出口无 `ENTER_PORTAL`/`UNLOCK_PORTAL` 候选；警察不能使用通道。
- 中途结束：清活动光球、丢弃未发布事件，不补播到达。

**测试：** 传送时间线 400–429/430；双方 `transits` 一致；警察普通 `opponent=null`；小偷 `self` 位置公式；携任务物资传送；传送中移动/交互/道具/再次进入无效；落地清输入且需松手；落点恢复隐藏/可见；事件只一条；终局清光球；新局清空；出口无候选；警察不能进入。

**验收：** `V2WireCodec` 的 snapshot 约束能接受双方视图（重点：`transits` 至多一条、`self.motion`、警察 `opponent=null`、光球坐标公式）。

### A12 视图权限、整局回归、校验与交接

**目标：** 把所有新增状态完整投影、补边界、跑整局脚本，给 B/C 可用的交接说明。

**实现：**

- 完整 `V2ViewProjector`：`inventory`、`effects`、`groundItems`、`groundCards`、`portals`、`transits`、`thief` 私有字段、`originStatus`、`ackInputSeq`。
- 隐藏信息审计：警察无小偷卡槽/保护截止/携带物资/地面任务物资坐标；隐藏小偷不出现；光球是唯一公开例外。
- `visibilityChanged` 覆盖首拍、显隐切换、保护变化、拾取/使用/解锁、光照强化、传送开始/结束、结算。
- 新局清理：库存、效果、卡、通道、光球、事件、动作缓存、输入和交互锁。
- 完整单步顺序按 02 §13.8 固化：动作 → 移动/瞄准 → 照射/标记 → 丢弃 → 双角色交互 → 结局 → 投影。
