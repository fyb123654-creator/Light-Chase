## 1. 我们负责什么

我们负责 A：游戏规则，也就是整局游戏的“裁判”。

- 输入：B 每一拍送来的 `StepInput`（tick、双方操作、退出事件）。
- 输出：`StepResult`（这一拍结束没有、谁赢）、每个玩家的 `PlayerView`。
- 约束：纯 Java，不依赖 Android、libGDX、WebSocket、系统时钟；确定性、可单测。
- 不负责：Android 界面、WebSocket、服务器房间/倒计时、客户端插值；这些是 B/C 的部分。
- 不改线上契约：发现契约真缺字段，先停下来记录，再和 B/C 一起改。

## 4. 分步说明

### A1 数据关（已完成）

**目标：** 坏地图/坏规则在启动时立即报错，而不是打到一半 NullPointerException。

**已实现：**

- 严格 JSON：缺字段、未知字段、错类型、null、非有限数字都拒绝；递归重复键、非标准语法、尾随 JSON 和非法 UTF-8 拒绝，嵌套深度上限 64。
- 地图固定 24×18；`mapId` 非空；`mapVersion >= 1`。
- 墙体坐标在 `0..23 × 0..17`，不能重复。
- 出生点恰好 POLICE/THIEF，坐标有限且可站立。
- 物资恰好 M1/M2/M3，交付点恰好 D1/D2/D3，出口恰好 E1/E2；ID 唯一。
- 每件物资绑定存在且唯一的同编号交付点：M1→D1、M2→D2、M3→D3；交换绑定也必须拒绝（本轮审查补强）。
- 物资/交付/出口坐标有限、可站立，且彼此不重叠。
- 所有自由格连通；出生点、物资、交付点、出口都可达。
- 出生点不能一开局就在警察 4 格 60° 光束内。
- 规则参数合法；`tickRate = 30`、`durationTicks > 0`、`maxMarks >= 1`、`radius < 0.5` 等。

**测试：** 本轮 DataFilesTest 26 项、MapTopologyTest 6 项；数据模块 32 项、checkJvm 63 项全过，Android debug 构建通过。初版为 19+6 项。当前测试地图 24×18、88 面墙、344 个自由格全连通，地图 hash `19b3f00c…f07d24f`，规则 hash `1db72fcc…b6e9230d1`。

**遗留：** 可达性是格级 4 方向 BFS；A6 正式地图仍要按角色半径 0.25 复核交互站位。

### A2 骨架关（下一步）

**目标：** 把移动原型升级成真正的比赛状态机。

**新增/修改：**

- `V1EngineFactory`：B 的创建入口。
- `V1MatchEngine`：每拍校验 tick、合并输入、移动、收集退出、步末统一裁决、返回 `StepResult`。
- `MatchState` / `ActorState`：保存双方位置、朝向、输入记忆、tick、结果。
- `InputMerger`：按收到顺序扫描同拍命令，得到最终方向、是否有非零移动、最终是否按住、按下/释放边沿、新 dropId。
- `ViewProjector`：先生成基础 `PlayerView`。
- `RuleMath`：半角、视野半宽、朝向归一化。
- `PrototypeEngineFactory` / `MovementPrototypeEngine`：保持旧入口与行为；新引擎使用独立 V1EngineFactory。每阶段标注支持/不支持的操作，与 B 联合验收后才切换默认入口、迁移旧测试并决定删除。

**旧入口保护：** 保留旧工厂期间增加回归测试，确认 `PrototypeEngineFactory` 仍返回旧行为；B 必须显式使用 `V1EngineFactory`，不能因为类名带 V1 就默认已经切换。联合验收后再迁移默认入口并决定删除旧实现。

**每拍顺序：**

```text
1. 已结束：返回原结果，不推进 tick
2. 校验 tick == 上次 + 1
3. 校验玩家、数值范围、dropId
4. InputMerger 合并本拍命令
5. 更新保护状态（A3 才有，先留位置）
6. 移动：最终方向归一化，整拍只走 1/30 秒，先 X 后 Y 分轴碰撞
7. 收集退出事件，按 playerId 去重，不立即 end
8. 步末统一裁决：先超时；无正常结局时，两名玩家离开判 BOTH_LEFT，恰好一名离开判另一方胜。A3/A4 在此统一裁决器中增加抓捕/撤离候选
9. 投影视图，返回 StepResult
```

**退出与正常结局同拍：** 退出事件只影响步末裁决，不撤销本步已经发生的移动、照射、交互；提交 `Departure` 的玩家本步命令仍按普通命令处理。步末先判超时/抓捕/撤离，再按去重后的离开人数判负。

**验收：** 斜向不加速；撞墙/沿墙滑动；停下保持朝向；多条命令一拍只动一次；第 5400 拍超时；单方退出另一方胜；双方同拍退出 `BOTH_LEFT`；结束后幂等；tick 不连续抛错。补充测试：小偷退出+同拍撤离→`ESCAPED`；警察退出+同拍第三次标记→`CAPTURED`；单方退出无正常结局→另一方胜；双方退出→`BOTH_LEFT`。

### A3 视野关

**目标：** 手电、墙挡光、小偷矩形视野、标记累计、隐身/免疫、警察视图不泄露。

**新增/修改：**

- `MatchState` / `ActorState`：保护状态、`beamProgress`、可见性布尔值。
- `V1MatchEngine`：步开始更新保护 → 移动 → 判断手电 → 累计/清零 → 第 24 拍标记 → 取消交互。
- `ViewProjector`：警察 `thief=null`、只有有效光照且非隐身才给 `opponent`；小偷 `thief` 必须是对象。
- `RuleMath`：`inBeam`/`inViewRect` 所需的半角、视野半宽。
- `VisibilityMarkingTest`。

**时间线：**

```text
第 k 拍：照满 24 拍，marks++，进入 INVISIBLE
k … k+44：隐形，remaining 45 → 1
k+45 … k+74：免疫，remaining 30 → 1
k+75：普通，remaining 0
```

**验收：** 第 23/24/25 拍边界；中断后重新照从零累计；隐身不可见/免疫可见但不累计；墙后、超距、超角不可见；第三次标记 `CAPTURED`；警察视图 `thief=null`。

### A4 任务关

**目标：** 三件物资、拾取、交付、丢弃、重新拾取、出口、撤离。

**新增/修改：**

- `MaterialState`：`GROUND` / `CARRIED` / `DELIVERED`；ID、绑定交付点、地面坐标、`everPicked`。
- `InteractionState`：`candidate`、`active`、`progressTicks`、`requiresRelease`、`blockedReason`。
- `MatchState`：初始化物资；维护 `carrying`、`delivered`、`exitsOpen`；候选选择、完成效果。
- `V1MatchEngine`：标记 → 丢弃 → 交互 → 胜负。
- `ViewProjector`：小偷私有视图补全；警察仍然看不到。
- `InteractionTest`。

**交互状态机：**

```text
无交互
  → 按下（合法目标）→ active，progress=1
  → 每拍按住 → progress+1
  → progress=30 → 完成，requiresRelease=true，active=null
  → 松手 → requiresRelease=false

取消条件：
  松手 / 移动尝试 / 被标记 / 丢弃 / 目标失效
  → progress=0，active=null
  → 如果还按着，requiresRelease=true，必须松手再按
```

**候选优先级：** 可交付 > 可拾取（最近，同距按 ID）> 可撤离。

**验收：** 0.8 格、无墙、静止 30 拍；松手/移动/被标记/丢弃/目标失效清零；错误交付不接收；丢回原点 `everPicked` 仍 true；三次交付开出口；出口开放前不能撤离；§12.2 输入表逐行通过。字段验收使用精确名称：`originStatus`、`ThiefPrivate.carriedMaterialId`、`groundMaterials`、`candidate/active/progressTicks/requiresRelease/blockedReason`；对手可见时另验 `VisibleOpponent.carrying`。

### A5 收尾关

**目标：** 结局优先级、同拍冲突、abort、幂等、完整视图、整局回归。

```text
超时（警察胜）
  > 第三次标记（警察胜）
  > 撤离成功（小偷胜）

没有上述正常结局时：先统计本步去重后的离开人数
  两人 → BOTH_LEFT，无胜方（包括 QUIT + DISCONNECT 等混合原因）
  一人 → 离开方输
  零人 → 继续对局
```

**新增/修改：**

- `V1MatchEngine`：每拍末尾按优先级检查；`end()` 只创建一次 `MatchResult`；`abort()` 未结束才生成 `SERVER_ABORTED`。
- `MatchState`：`captured`、`escaped`、`result`、`ended`。
- `ViewProjector`：终局视图完整。
- `OutcomeTest`、`FullMatchTest`。

**验收：** 同拍多条件只出一个结果；正常结束优先于退出/掉线；双方同拍退出 `BOTH_LEFT`；结束后 step 返回同一结果；新建引擎状态重置；完整一局能跑通；双方视图一致；警察无私有信息。

## 5. 关键规则口径

| 事项 | 口径 |
|---|---|
| tick | 第一拍 `tick=1`；引擎不读系统时钟；不连续抛错 |
| 移动 | 最后一条命令决定方向；整拍只动一次；斜向归一化；先 X 后 Y；子步 ≤0.1 格 |
| 朝向 | 最终非零移动方向；停下保持；撞墙也按输入方向转 |
| 标记 | 第 24 个连续有效照射拍标记；中断清零；第三次直接结算 |
| 保护 | k 拍标记：k..k+44 隐身（remaining 45），k+45..k+74 免疫（remaining 30），k+75 普通 |
| 交互 | 0.8 格、无墙、静止、按住 30 拍；第 1 拍计 1；完成后必须松手重按 |
| 取消 | 松手 / 移动尝试 / 被标记 / 丢弃 / 目标失效，清零；按住时要求先松手 |
| 丢弃 | 边沿动作，立即落在移动后脚下；隐身允许；同拍最多一件；重复 dropId 只消费一次 |
| 优先级 | 超时 > 第三次标记 > 撤离；正常收尾 > 退出/掉线；双方同拍失联 BOTH_LEFT |
| 警察视图 | `thief=null`；只有有效光照且非隐身才给 `opponent`；不给地面物资坐标、携带编号、保护计时 |
| 小偷视图 | `thief` 必须是对象；给保护状态、地上物资、已交付列表、交互进度 |
| 传输字段 | `serverTimeMs`、`ackInputSeq` 由 A 返回 0，B 复制后填；A 不读 `countdownTicks` |
| 数据 | V1 固定 24×18、M1–M3、D1–D3、E1–E2、`tickRate=30`；坏数据启动即报错 |

## 6. 给 B 的接口（不变契约，只换实现）

```java
MatchEngineFactory factory = new V1EngineFactory();
MatchEngine engine = factory.create(map, rules, init);

StepResult step = engine.step(new StepInput(tick, commands, departures));
PlayerView policeView = engine.viewFor(policePlayerId);
PlayerView thiefView = engine.viewFor(thiefPlayerId);
MatchResult result = engine.result(); // ACTIVE 时为 null
```

创建后可用 `viewFor` 读取 tick=0 视图。B 按 30Hz 调 `step`，每次 step 返回后按快照策略分别读取双方视图；不是等整局结束才读取。首个逻辑步、对手显隐切换、结算步的 visibilityChanged=true，B 据此及时发送。结果只提交一次。A 不碰 JSON、WebSocket、Android、libGDX、系统时钟。

1. 当前沙箱不允许 Gradle 写 `~/.gradle`，旧 `build/reports/problems` 也有 ACL 限制。A1 使用临时 `GRADLE_USER_HOME`、`GRADLE_RO_DEP_CACHE` 和临时 build 目录跑通；不把构建 hack 提交进仓库。Android debug 构建还需把 `ANDROID_USER_HOME` 指向临时目录并复制 `debug.keystore`，否则沙箱写 `~/.android/debug.keystore.lock` 会被拒绝；这是环境差异，不是仓库配置。
