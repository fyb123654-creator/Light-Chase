# Light Chase 联调与验收手册

日期：2026-10-23；R1。本文是测试计划与验收方法，不是通过报告。S0 已执行 18 项测试并记录在 [验证记录](../verification/2026-10-23_S0.md)；S1 及之后的玩法用例仍未执行，不能据此宣称 V1 验收通过。

## 1. 开发顺序与交接物

不制定固定日期，按可验收的产物推进。每一项在任务板记录 TODO/DOING/REVIEW/DONE、负责人、对应需求及实际验证证据。

| 阶段 | A | B | C | 阶段出口 |
|---|---|---|---|---|

| S1 分头最小闭环 | 无网络移动/碰撞/计时引擎及测试 | 假引擎下两客户端握手、选角、准备、倒计时 | FakeGateway 下连接/大厅/对局/结算页面与摇杆 | 各模块不依赖别人的未完成业务也能演示 |
| S2 双机移动 | 输出双方位置和警察朝向 | 真引擎集成、20Hz输入/15Hz快照、心跳 | 双模拟器渲染真实状态、适配、释放输入 | 两端移动一致、碰撞正确，暂停不残留移动 |

| S4 取送闭环 | 拾取、交付、丢弃、出口与冲突顺序 | 幂等、结果确认、返回大厅、重开 | 按住按钮、进度、丢弃、结算重开 | 小偷胜利路径完整；A01–A22回归 |

不要一开始让 C 等待全部服务器完成；也不要用真实网络时延来调试尚未确定的核心规则。先用替身验证自己的边界，再进入双机集成。

## 2. 替身与测试工具责任

S0另含[开源方案](06_开源参考与复用方案.md)的源码阅读与选用检查；实际引入的代码必须通过OS01–OS05，交付时附[复用登记表](07_开源复用登记表.md)。未确定复用的模块可以继续按契约独立开发，不将原项目测试通过当成本项目测试通过。

### A 的规则测试驱动

使用固定地图、固定 MatchInit 和人工 StepInput 推进整数 tick。能设置测试出生位置/状态，用于边界用例，但这些入口不暴露给运行时网络。断言位置、计数、保护阶段、结果及双方视图。每个失败输出 tick、输入序列和状态差异；禁止依赖真实等待0.8秒导致随机失败。

### B 的假客户端和假引擎

提供可本机运行的协议客户端或集成测试，模拟两条独立 WebSocket，发送规范控制及输入消息，查看脱敏输出。假引擎只用于网络模块测试，固定输出可辨识的 TEST_ONLY 状态，不复制完整游戏规则。编解码测试从真实 contracts 类型生成样例并往返验证，测试非法字段与枚举。

### C 的 FakeGateway

实现相同 ClientGateway，脚本依次发送 CONNECTED、大厅、倒计时、警察视图、小偷视图、隐身/免疫、交互进度、断线、结算和重开。onView 只用合法角色视图，不给 C 一个完整 MatchState 再让其自己删字段。记录收到的 InputFrame 用于检查多指触摸、释放和丢弃脉冲。

调试入口只在开发构建启用；真实发布组装必须注入 WebSocketClientGateway，不可误用 FakeGateway。纯规则、协议和 UI 三套测试各自不需要模拟对方的内部实现。

## 3. 测试环境与记录

- 当前手机型号和 Android 版本未知。先用两个独立 Android 模拟器实例；不能用同一进程开两个本地角色替代两条连接。
- 启动服务端并记录监听地址/端口，模拟器使用其到电脑的有效地址，真机使用电脑局域网地址；不要把真机的 localhost 当成电脑。
- 模拟器网络地址应按所选模拟器官方说明验证，写入实际运行手册，不在代码中写死；用两个实例完成从连接页操作的测试。
- 两个不同屏幕比例与分辨率分别截图，验证世界显示范围相同。模拟器通过不代表真机触控、多指输入、Wi-Fi 或系统后台行为已通过。
- 最终基础需求仍是两台 Android 设备对局；若暂时没有真机，报告“模拟器验证通过、真机验证待完成”，不能将 A01–A22 的真机验收签为全部通过。

建议测试记录格式：


## 6. 运行故障排查顺序

1. 核对客户端和服务端协议、地图、规则哈希一致。
2. 确认服务器进程运行、监听地址与端口正确；查看启动日志，不把手机连接失败直接当成游戏逻辑问题。
3. 检查电脑与设备之间网络可达、防火墙、热点隔离和模拟器地址。防火墙改动由实际操作者确认环境后执行。
4. 查看握手/入房错误码，确认未连接到旧服务器进程。
5. 连接正常但无画面先看是否收到RUNNING和SNAPSHOT；收到合法视图但没绘制由C查线程与资源。
6. 画面与规则不符先用相同输入复现A的规则测试；如果正确，再查B序号/调用顺序和C插值。
7. 可见性问题同时看服务端角色视图、实际序列化payload和客户端缓存，三层不能只查一层。

## 7. 完成定义与交付清单

每项功能必须：按契约实现、模块可编译、对应测试通过、正常和失败路径可演示、无权限泄漏、需求/示例更新。AI生成代码的“看起来完整”不是完成证据。

发布包至少包含：APK、可运行服务端包或明确启动方式、源码提交、构建依赖锁定记录、地图/规则及hash、启动说明、测试记录、已知问题、复用库及许可记录。首次运行无需修改源码即可配置host/port/room。

先完成模拟器演示，再按设备条件补真机检查；缺设备项保留未测。不得用未实现的传感器、钥匙或精美素材掩盖基础对局未完成。
