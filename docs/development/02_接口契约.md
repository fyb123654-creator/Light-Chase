# Light Chase V1 接口契约

契约版本 `protocolVersion=1`；日期 2026-10-23；R1，建议实现基线。除既定玩法外，下列接口、字段、错误码与传输策略为本次补齐的工程约定。修改需三方同步，禁止在各模块自行增加同名不同义字段。

## 1. 统一类型与约束

- string 为 UTF-8，ID 大小写敏感，服务器生成 sessionId/playerId/matchId/resultId，客户端不得选择或伪造 playerId。房间号按开发设计规范化。
- int 为有符号 32 位整数；long 在 JSON 中使用非负整数且不超过 2^53−1；float/double 必须有限，拒绝 NaN/Infinity。位置与角度用 double，传输不要求小数位固定。
- Role=`POLICE|THIEF`；RoomPhase=`LOBBY|COUNTDOWN|RUNNING|FINISHED`；Protection=`NORMAL|INVISIBLE|IMMUNE`；InteractionType=`PICKUP|DELIVER|ESCAPE`。
- Position=`{x:double,y:double}`；Pose=`{x:double,y:double,headingRad:double}`。坐标单位和方向见开发设计。这是接口描述用的概念记法，代码中对应 `MapPoint`、`SpawnPose`、`ActorPose`，字段以 contracts 中的类为准。
- 下文 `T?` 表示字段必须存在但允许 null，`[T]` 表示数组可为空；没有 `?` 的字段必填且不得 null。只有明确写“禁止出现”的角色私有字段才完全省略。未经版本升级的未知字段、枚举、消息类型均拒绝，避免静默误解。
- 所有模型使用普通不可变 DTO 或构造后不修改的副本；禁止将引擎内部集合引用交给客户端或网络线程。

## 2. 进程内 Java 契约

以下为接口设计签名；DTO 的字段在后文定义。客户端不依赖内部 MatchState。

```java
public interface MatchEngineFactory {
    MatchEngine create(MapDefinition map, RuleConfig config, MatchInit init);
}
public interface MatchEngine {
    StepResult step(StepInput input);
    PlayerView viewFor(String playerId);
    MatchResult result(); // ACTIVE 时 null，结束后固定值
    MatchResult abort();  // 服务端无法继续时；未结束则SERVER_ABORTED，否则返回既有结果
}
public interface ClientGateway {
    void connect(ConnectionOptions options, GatewayListener listener);
    void selectRole(Role role);
    void setReady(boolean ready);
    void submitInput(InputFrame frame);
    void returnToLobby();
    void leaveRoom();
    void background();
    void close();
}
public interface GatewayListener {
    void onConnection(ConnectionStatus status);
    void onRoom(RoomState state);
    void onView(PlayerView view);
    void onResult(MatchResult result);
    void onError(GatewayError error);
}
```

`MapDefinition`、`RuleConfig` 的字段定义在 [开发设计](01_分工与开发设计.md) 第 8 节（地图与配置交付），`RoomState`、`PlayerView`、`MatchResult` 在本文件第 6–8 节。本节只锁定接口签名，不重复字段表，避免两处各写一份。

所有客户端方法非阻塞；错误走 onError，不用异常穿过渲染线程。connect 正在连接或已连接时重复调用返回本地 ALREADY_CONNECTED，不偷偷创建第二个会话。close 幂等，清空缓存和输入；正在对局的用户主动离开须先调用 leaveRoom/background 表明原因，close 仅清理资源。

GatewayListener 在网关线程回调；C 负责入队到渲染线程。C 持续每帧更新 InputFrame，B 负责 20Hz 发送、边沿即时发送、心跳、序号、包络和自动 RESULT_ACK。C 不自己构造 JSON、计算 inputSeq 或处理 socket 断线。

若ClientGateway连续250ms未收到新的submitInput调用，应发送零向量与interactHeld=false，并清掉待发送drop脉冲；即使网络线程仍在运行，也不能无限重发渲染卡住前的操作。输入采样刷新和网络心跳是两个不同租约。

| 类型 | 完整字段/语义 |
|---|---|
| ConnectionOptions | host:string, port:int, roomId:string, clientBuild:string, mapHash:string, configHash:string。protocolVersion 由编译契约常量设置 |
| ConnectionStatus | state:`DISCONNECTED|CONNECTING|HANDSHAKING|JOINING|CONNECTED|SUSPECT|CLOSED`, reason:string?；CONNECTED 指已加入房间 |
| GatewayError | code:string, message:string, recoverable:boolean, requestId:string?；本地错误 requestId=null |
| InputFrame | moveX:double, moveY:double, interactHeld:boolean, dropPressed:boolean；dropPressed 是本次提交的瞬时脉冲，B 必须保留而非用后续帧覆盖 |
| MatchInit | matchId:string, policePlayerId:string, thiefPlayerId:string；角色不同且非空。初始 pose 来自地图，tick=0 |
| StepInput | tick:long（严格上次+1）, commands:[PlayerCommand], departures:[Departure]。B 固定步调用；A 不读系统时钟 |
| PlayerCommand | playerId:string, inputSeq:long, moveX:double, moveY:double, interactHeld:boolean, dropId:long?。B 按收到次序提供，A 二次校验角色与状态 |
| Departure | playerId:string, reason:`QUIT|BACKGROUND|DISCONNECT`；同一步相同玩家去重 |
| StepResult | tick:long, visibilityChanged:boolean, ended:boolean, result:MatchResult?。ended=true 时 result 必须非空；B 随后分别调用 viewFor |

B 管理 250ms 输入租约：到期向本步引擎提交归零释放命令；该内部命令不消耗网络 inputSeq，PlayerCommand 此时沿用最后 inputSeq，A 的去重只过滤相同序号的离散 dropId，不能忽略租约释放。更清楚的实现可在 StepInput 增加 `expiredPlayerIds:[string]`，但那属于契约变更，不能两种同时使用。本版固定采用归零命令，并在 B 入队前完成网络 inputSeq 去重。

A 的 step 结束后再次调用必须返回同一结果且不改状态；非法 tick 或未知 playerId 为编程错误，记录并让 B 终止该房间 SERVER_ABORTED，不崩溃整个服务端。viewFor 未知玩家抛受控参数错误；B 不得把该异常信息直接发给其他玩家。

abort也必须在该房间逻辑线程调用，A生成winner=null的SERVER_ABORTED结果；B不得另造与引擎不同的结果。若引擎自身损坏导致abort也无法安全完成，B关闭连接并显示SERVER_ERROR，不能发送未经确认的胜负。

单步判定顺序以 [开发设计](01_分工与开发设计.md) 第 5 节为准（保护截止 → 移动 → 光照/标记 → 丢弃 → 交互 → 胜负 → 投影），本契约不另立顺序。`visibilityChanged` 的定义：本步任一玩家的 `opponent` 由 null 变非 null 或反之、首步、结算步均为 true，其余 false。引擎结束后再次调用 `step` 仍返回同一 `result` 且 `ended=true`，不得继续推进 tick。

## 2.1 共享几何 API（contracts.geometry.WorldGeometry）

A 提供、B 审核、C 复用；全部是纯函数，不读时钟、不访问网络，服务端判定与客户端绘制必须使用同一套实现：

```java
boolean canStand(MapDefinition map, double x, double y, double r)
double  distance(double x1, double y1, double x2, double y2)
boolean segmentBlocked(MapDefinition map, double x1, double y1, double x2, double y2)
boolean inBeam(MapDefinition map, double px, double py, double headingRad,
               double tx, double ty, double range, double halfAngleRad)
boolean inViewRect(double px, double py, double tx, double ty,
                   double halfWidth, double halfHeight)
```

- 容差统一 1e-6；墙体为闭方块，擦墙角也阻挡视线（`segmentBlocked` 返回 true）。
- `inBeam` 同时检查距离、与朝向夹角、墙体遮挡；距离为 0 时只跳过夹角检查，仍做遮挡与保护判断。
- `inViewRect` 是小偷观察警察的矩形范围，包含边界，不受墙遮挡。
- `canStand` 同时要求不出地图边界、不与墙重叠；地图外不可走。

C 只能用这些方法绘制光束与对手可见范围，不能用本地几何覆盖服务端对 `opponent` 的决定（见第 7 节）。

## 3. WebSocket 通用包络

所有消息为一个完整 UTF-8 JSON 文本对象，不在一个 frame 内拼多条对象，不使用二进制。单消息最大 64KiB（UTF-8 字节）；超过限额拒绝并关闭。应用消息队列设上限，快照允许丢旧保新，控制/结果不得静默丢弃。

```json
{"v":1,"type":"INPUT","seq":12,"requestId":null,"matchId":"m-001","body":{"inputSeq":7,"moveX":1.0,"moveY":0.0,"interactHeld":false,"dropId":null}}
```

| 字段 | 类型 | 契约 |
|---|---|---|
| v | int | 必须 1；HELLO 也使用该包络，版本不兼容返回错误后关闭 |
| type | string | 下列目录中的精确类型 |
| seq | long | 每连接、每方向从 1 严格递增；每条新消息占一个序号；重复或倒退丢弃并报告一次 STALE_MESSAGE |
| requestId | string? | 控制请求必填，1–64 字符；服务器响应关联同值；广播、输入和心跳为 null |
| matchId | string? | INPUT/结果确认/游戏视图/结果须为当前局 ID；房间控制为 null；ERROR 使用对应请求的 matchId |
| body | object | 必须符合消息类型模型，不含完整 MatchState |

服务器不接受客户端 body 中 playerId、胜方、位置或计数；会话绑定决定发送者。服务器出站 seq 每个连接单独增长，不用房间共享序号。HELLO 返回 sessionId 仅用于诊断，不作为可跨连接恢复的 token。

请求处理语义：可靠有序 WebSocket 上不做应用自动重发；UI 控制按钮等 ACK/ERROR 再解锁，2 秒未响应提示等待，5 秒无响应关闭连接。若重复 requestId 到达且请求类型/内容一致，返回缓存原 ACK/ERROR，不重复执行；内容不同返回 REQUEST_ID_REUSED。缓存当前连接最近 128 个控制结果；淘汰后的旧请求不得自动补发。输入按 inputSeq 去重，dropId 在本局内单调增长且仅消费一次。包络 seq 防过期消息，requestId 防控制重执行，inputSeq/dropId 防动作重复，职责不同。

## 4. 客户端 → 服务端消息全集

每一条均受包络约束；表中列出 body 的全部字段。

| type | body | requestId / matchId | 合法状态、处理与响应 |
|---|---|---|---|
| HELLO | clientBuild:string, mapHash:string, configHash:string | 必填 / null | 新连接第一条；验证版本与资源，响应 WELCOME；3秒内未收到关闭 |
| JOIN_ROOM | roomId:string | 必填 / null | WELCOME 后；创建或加入房间，ACK 后发送 ROOM_STATE；一个连接只加入一个房间 |
| SELECT_ROLE | role:Role | 必填 / null | LOBBY/COUNTDOWN；占位串行处理，变更取消倒计时并清双方准备；选原角色为无副作用成功 |
| SET_READY | ready:boolean | 必填 / null | LOBBY/COUNTDOWN；true 需要已有角色；false 取消倒计时并清双方准备；重复同值无副作用 |
| INPUT | inputSeq:long, moveX:double, moveY:double, interactHeld:boolean, dropId:long? | null / 当前局 | 仅 RUNNING；无逐条 ACK，SNAPSHOT.ackInputSeq 确认处理到的位置；警察的交互/drop 拒绝 INVALID_ACTION |
| HEARTBEAT | nonce:long | null / null | WELCOME 后任何阶段，每秒；PONG 原样回 nonce |
| LEAVE_ROOM | reason:`QUIT|BACKGROUND` | 必填 / null | 已入房间任意阶段；RUNNING 时转成 Departure；ACK 后解除成员关系并关闭该连接 |
| RETURN_LOBBY | resultId:string | 必填 / 当前局 | FINISHED；必须匹配结果；ACK 后 ROOM_STATE；重复请求幂等 |
| RESULT_ACK | resultId:string | null / 当前局 | FINISHED；停止本连接重复 GAME_OVER，不改准备或房间状态 |

INPUT 的 inputSeq 在每个 matchId 从 1 起递增。B 在发送 dropPressed 时分配 dropId 从 1 起递增；同一 drop 脉冲只发一次，后续 input 的 dropId=null。游戏输入在 RUNNING 前、结束后、旧 matchId、未知/越界数值一律拒绝。网络接受合法输入不等于玩法操作成功，是否可拾取由后续快照决定。

RUNNING时LEAVE_ROOM必须先排入本步Departure，保持会话到规则提交结果，再依次尽力发送GAME_OVER、ACK并解除房间/关闭连接；不能先删除成员导致引擎无法识别退出者。另一方正常收到结果。后台或网络已关闭的一方不保证收到结算；回到前台显示中断，不能猜测服务器最终结果。大厅和结算期离开直接ACK并清理，无需创建新结果。

已加入房间的连接再次JOIN_ROOM：同房间为无副作用成功并重发ROOM_STATE；其他房间返回INVALID_PHASE，必须先离开并重新连接。SELECT_ROLE/SET_READY等请求只能影响当前会话自己的角色和准备状态。

## 5. 服务端 → 客户端消息全集

| type | body | requestId / matchId | 处理 |
|---|---|---|---|
| WELCOME | sessionId:string, playerId:string, protocolVersion:int, mapHash:string, configHash:string, heartbeatMs:int, disconnectMs:int | HELLO 的值 / null | 启动心跳，自动 JOIN_ROOM；哈希必须与请求一致 |
| ACK | action:string | 请求值 / 请求值 | 仅表示控制动作已接受；客户端仍以 ROOM_STATE 为占位/准备依据 |
| ERROR | code:string, message:string, fatal:boolean | 请求值或 null / 对应值或 null | message 为显示文字，不含堆栈；fatal=true 后关闭 |
| ROOM_STATE | RoomState | null / null | 大厅、倒计时、运行、结算状态变更即广播；倒计时每100ms广播 |
| SNAPSHOT | PlayerView | null / 当前局 | 全量角色视图，替换旧视图；不做字段合并或保留消失敌人 |
| GAME_OVER | MatchResult | null / 当前局 | 幂等展示结算、停止输入；B 自动 RESULT_ACK；接收后不再应用该局旧快照 |
| PONG | nonce:long, serverTimeMs:long | null / null | serverTimeMs 为进程单调时间毫秒，不是日期；用于 RTT/显示估计，不授予客户端判定权 |

ROOM_STATE 中 RUNNING 先于首个 SNAPSHOT 发送；首个 SNAPSHOT 含 tick=0 或服务器当前步，客户端收到两者后开始操作。GAME_OVER 前可发终局 SNAPSHOT，但客户端不能依赖它必须到达；GAME_OVER 自带完整结算字段。

## 6. RoomState 完整模型

```text
roomId:string
revision:long                 # 房间状态变化时递增，倒计时更新时间也递增
phase:RoomPhase
mapId:string
mapHash:string
configHash:string
matchId:string?               # RUNNING/FINISHED 非null；LOBBY/COUNTDOWN null
countdownRemainingMs:int      # COUNTDOWN 为0..3000，其他为0
players:[RoomPlayer]          # 长度0..2，按加入顺序
RoomPlayer = {playerId:string, role:Role?, ready:boolean,
              connection:"CONNECTED"|"SUSPECT", returned:boolean}
```

客户端自身 playerId 来自 WELCOME，据此标记“我”；没有用户名或登录。returned 只在 FINISHED 有意义，其他阶段 false。对局中 connection 显示网络健康，不包含任何敌方坐标或保护状态。哈希不匹配不能开局。

## 7. PlayerView 完整模型与权限

```text
matchId:string
tick:long
serverTimeMs:long
ackInputSeq:long             # 本玩家已消费的最高网络inputSeq，无输入为0
role:Role
remainingTicks:int          # 0..5400
marks:int                   # 0..3，公共
deliveredCount:int          # 0..3，公共
exitsOpen:boolean
self:ActorPose
opponent:VisibleOpponent?   # 不可见必须null，不发送最后位置
originStatus:[{materialId:string,everPicked:boolean}] # 恰好M1..M3，双方公开
thief:ThiefPrivate?         # POLICE必须null；THIEF必须对象
ActorPose = {playerId:string,x:double,y:double,headingRad:double}
VisibleOpponent = {playerId:string,role:Role,x:double,y:double,
                   headingRad:double,carrying:boolean}
ThiefPrivate = {
  carriedMaterialId:string?,
  protection:Protection,
  protectionRemainingTicks:int,
  groundMaterials:[{materialId:string,x:double,y:double}],
  deliveredMaterialIds:[string],
  interaction:InteractionView
}
InteractionView = {
  candidate:InteractionTarget?,
  active:InteractionTarget?,
  progressTicks:int,
  requiresRelease:boolean,
  blockedReason:"NONE"|"INVISIBLE"|"MOVING"|"NO_TARGET"|"RELEASE_REQUIRED"
}
InteractionTarget = {type:InteractionType,targetId:string}
```

PlayerView 的 serverTimeMs/ackInputSeq 是 B 在 A 产生语义视图后补齐的传输元数据：A 的 viewFor 返回这两个字段的默认 0，B 复制 DTO 填入，不修改其余字段；更改字段归属须更新此说明。tick 和 remainingTicks 由 A 生成。

权限与渲染约束：

1. 静态墙体/起始点/交付点/出口坐标由共同地图读取，不重复放进每帧快照。
2. 警察只得到 originStatus 和交付总数；`thief=null`，无地面丢弃物资坐标、交付具体 ID、携带物资 ID、保护计时、敌人交互目标或进度。不得在其他顶层字段或错误信息泄露这些信息。
3. 警察看见小偷时 opponent 可含其当前位置、方向和 carrying 布尔值，仅用于同时显示携带外观；隐藏时整个 opponent=null，携带外观一起消失。没有独立携带物坐标。
4. 小偷 groundMaterials 包含全部当前地上物资（包括原点和丢弃位置），主画面自行按镜头裁剪，小地图全部显示；已携带/交付的不在数组中。
5. 小偷看见警察的矩形范围由 A 计算；警察 carrying 永远 false。对手显示没有额外公开保护状态字段。
6. candidate 是当前合法目标，用于按钮文案；active 是正在累计的锁定目标；无活动时 progressTicks=0、active=null。交互完成后 requiresRelease=true，松开后解除。INVISIBLE 时 candidate/active=null。
7. protectionRemainingTicks 只计当前阶段剩余步数；NORMAL 为0。边界固定为：在第 k 步完成一次标记，同一步视图即 INVISIBLE、remaining=45，k..k+44 为隐身；k+45 起 IMMUNE、remaining=30（k+45..k+74）；k+75 起 NORMAL、remaining=0。第三次标记直接结算，不再进入保护。免疫期间有效光照可见但不累计标记。无公共 markProgress 字段，避免泄露隐身或盲区信息。



## 8. MatchResult 完整模型

```text
resultId:string                 # 一局唯一，建议 matchId + ":result"
matchId:string
winner:Role?                    # ABORTED 时null
reason:"TIMEOUT"|"CAPTURED"|"ESCAPED"|"QUIT"|"BACKGROUND"|
       "DISCONNECT"|"BOTH_LEFT"|"SERVER_ABORTED"
departedPlayerId:string?        # 单方异常时玩家ID，其他null
elapsedTicks:int                # 0..5400
marks:int
deliveredCount:int
finalTick:long
```

本人胜负由客户端以 winner 与自己 role 映射为 WIN/LOSE；winner=null 显示“对局中断，无有效胜负”，不是平局计分。相同 resultId 的重复结果只处理一次；内容不同为服务端缺陷，客户端保留首个并记录。结果不含敌人终点、交付地点或本局轨迹。elapsedTicks 为服务器行动开始后的实际模拟步数，3秒倒计时不包括在内。

同一步同时满足多个收尾条件时，按 V1 §8.2 的优先级：超时 > 第三次标记 > 撤离成功。本步的退出/后台/掉线事件只在没有正常收尾时生效，正常收尾优先；若双方同时失联且无法区分先后，结果 BOTH_LEFT、winner=null。已结算的结果不能被后续异常覆盖（决策 D08）。

## 9. 错误码与恢复

| code | fatal | 说明及客户端动作 |
|---|---|---|
| BAD_MESSAGE | false，连续3次后true | JSON/字段/类型/未知字段不合法；控制操作恢复可点击 |
| MESSAGE_TOO_LARGE | true | 超过64KiB，关闭 |
| VERSION_MISMATCH / MAP_MISMATCH / CONFIG_MISMATCH | true | 显示更新或资源不一致，返回连接页 |
| HANDSHAKE_REQUIRED / HANDSHAKE_TIMEOUT | true | 未完成握手或超时，重新连接 |
| INVALID_ROOM_ID / NOT_IN_ROOM | false | 更正房间或先加入 |
| ROOM_FULL | false | 房间已有两人；换房间或等待，不踢已有玩家 |
| ROLE_TAKEN / ROLE_REQUIRED | false | 重新选择角色；不本地覆盖槽位 |
| INVALID_PHASE / STALE_MATCH | false | 不执行操作，等待当前房间/快照 |
| INVALID_INPUT / INVALID_ACTION | false | 越界非有限输入或角色无权动作；丢弃该命令，保留最近合法输入直到租约到期 |
| STALE_MESSAGE / STALE_INPUT | false | 旧序号丢弃，同类每秒最多反馈一次避免错误风暴 |
| REQUEST_ID_REUSED | false | 相同请求ID不同内容，拒绝 |
| RESULT_MISMATCH | false | 结果确认/返回请求与本局不符 |
| RATE_LIMITED | false，持续3秒后true | 输入超60/s或控制超10/s；拒绝超额并记诊断 |
| SERVER_BUSY | true | 建议首版最多8房间；达到上限拒绝新连接/建房 |
| SERVER_ERROR | true | 无法恢复的服务端会话错误，不能伪造胜负 |

本地 GatewayError 补充：INVALID_ADDRESS、CONNECT_TIMEOUT、CONNECTION_LOST、ALREADY_CONNECTED、NOT_CONNECTED；不发给服务器。结构合法但游戏条件不足（例如光照外、不可拾取）不反复 ERROR，按快照 candidate/blockedReason 表达。

## 10. 关键时序与背压

```text
C点击连接 → B建立WS → HELLO → WELCOME → JOIN_ROOM → ACK + ROOM_STATE
选择角色 → SELECT_ROLE → ACK + ROOM_STATE
双方准备 → SET_READY → ACK + ROOM_STATE(COUNTDOWN)
90步倒计时 → ROOM_STATE(RUNNING,new matchId) → SNAPSHOT
触摸 → INPUT → B入队 → A.step → A.viewFor(各玩家) → SNAPSHOT
规则结束 → GAME_OVER → RESULT_ACK → UI结算
各自返回 → RETURN_LOBBY → ACK + ROOM_STATE → 全员返回后LOBBY
```

网络回调给每房间入队；在固定步开始时原子取走当时所有待处理命令。迟到命令下步处理，不回滚历史。FIFO 处理控制与动作，连续移动可只保留最近值，但释放、按下、drop 脉冲必须按序保留。每连接输入队列建议128项，满时终止问题会话并走掉线流程，不能静默丢掉释放事件。

出站每连接最多保留一个尚未发送的快照，新快照替换旧快照；控制/结果独立有界队列64项，满时关闭慢客户端。隐藏事件产生的最新快照覆盖旧可见快照，但不可让旧快照在新快照后发送。客户端只接受更高 tick（或第一次同tick终局更新），按同一连接 seq 处理。跨局先清空插值/按键缓存，再接新局快照。

## 11. 契约变更和检查

Fugitive等外部项目参考或移植的实现必须适配本文接口，不将Godot节点、RPC对象或上游私有协议带入contracts。复用类型和来源按[开源方案](06_开源参考与复用方案.md)登记；发现必须调整接口时先更新契约、示例与三方实现。

B 维护 contracts 的源码与编解码，A 定义规则含义，C 核对显示与操作需要。新增字段必须同时更新本文、DTO、Codec、示例、假网关和测试。旧客户端不能默默加入新玩法局，改变必填字段/枚举/语义需提升协议版本并拒绝不匹配。

服务端日志只记录 roomId、matchId、seq、错误码、状态跃迁和受控诊断；客户端正常日志不输出对手隐藏位置。调试全状态只可在服务端受控测试中使用，不加入发布消息或 UI 开关。
