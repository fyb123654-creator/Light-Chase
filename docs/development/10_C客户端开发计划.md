## 1. 我们负责什么

我们负责 C：Android 客户端，也就是玩家看到的画面和摸到的操作。

- **输入**：B 的 `GatewayListener` 回调（`onSession`／`onRoom`／`onView`／`onControl`／`onResult`／`onConnection`／`onError`）；A 的逐角色 `PlayerView`。
- **输出**：`InputFrame`（摇杆、朝向、交互、丢弃）；控制指令走 `ClientGateway` 的既有方法（`selectRole`／`setReady`／`returnToLobby`／`leaveRoom`），不另造 DTO。
- **约束**：只做展示与输入，不实现规则判定；页面状态**只从 `RoomState.phase` 与连接状态推导**，不在客户端另存一份阶段；接口字段唯一来源是 [02_接口契约](../development/02_接口契约.md)；时间基准一律取 `RuleConfig`，不写死。
- **不负责**：规则判定（A）、WebSocket 编解码与房间/倒计时（B）、判分与验收。

**已实现：** JDK 21 定位（默认 JDK 25 不可用）、`local.properties` 指向 D 盘 SDK、`GRADLE_USER_HOME` 固定在 D 盘；`:app:assembleDebug`、`:server:installDist`、`checkJvm` 三条命令可复现。

**测试：** `checkJvm` 全过；APK 与 `server/bin/server.bat` 均产出。

**遗留：** 模拟器冷启动不稳定，属环境问题，已记录在本文 §8。

### 步骤 2 · `Available · Individual` · 离线大厅与错误流程（已完成）

**目标：** 没有服务器时，五个页面和错误提示也能完整演示。

**已实现：** 页面由 `RoomState.phase` 派生（LOBBY／COUNTDOWN／RUNNING／FINISHED），不另存阶段副本；契约 §9 有 23 个服务端错误码、本地另有 5 个 `GatewayError`，客户端可复现 6 个——替身返回 `CONNECT_TIMEOUT`／`ROOM_FULL`／`ROLE_TAKEN`／`INVALID_PHASE`，本地校验产生 `ALREADY_CONNECTED`／`INVALID_ADDRESS`，都有可读提示；`PENDING`/`WAITING` 期间禁用对应控件；致命错误回连接页并清空缓存。

**测试：** `checkJvm` 178 项（当时的基线）。

**遗留：** 真实服务器的 `SET_READY` 行为与替身不一致，见本文 §6。

### 步骤 3 · `Available · Individual` · 渲染与 HUD、触摸收口（已完成）

**目标：** 把对局画面画出来，并让操作在多指情况下可用。

**已实现：** 地图、墙、交付点、出口；警察光束用 `contracts.geometry.WorldGeometry.segmentBlocked` 做二分求交，与服务端判定同源；小偷矩形视野；小地图；HUD 按角色只显示允许的字段（警察永远收不到 `ThiefPrivate`）；触摸状态机抽出为 `TouchController`；手机 20.2:9 与平板 16:10 双比例实测。

**测试：** `checkJvm` 189 项；`TouchControllerTest` 10 项。

**遗留：** 截图要等 A/B/C 合并、界面定稿后统一拍摄，提前拍会因合并改动返工。

### 步骤 4 · `Available · Individual` · 真实网关与局域网权限（已完成）

**目标：** 能从替身切到真服务器，并且权限与连接失败说得清楚。

**已实现：** 连接页新增 `MODE: OFFLINE / LAN`；每次 LAN 连接新建网关实例，旧 socket 与监听器不串入新会话；切换模式时关闭旧传输；`ACCESS_LOCAL_NETWORK` 在**创建 socket 之前**申请，API < 37 视为不需要；回调统一入队、渲染线程消费；100 ms 插值；对局页显示 `NET <STATE> - <原因>`；旧传输在**四处**都会被关闭（错误路径、切换模式、重连前替换网关、`dispose`）；`SUSPECT` 与 `CONNECTED` 同等视为会话存活，不会把玩家踢回连接页。

**测试：** `checkJvm` 195 项（当时）；`ViewInterpolatorTest` 6 项。

**遗留：** `WebSocketClientGateway.error()` 只发 `onError`、不改 `ConnectionStatus`，客户端必须自行关传输兜底，见本文 §6。

### 步骤 4 · `Available · Cooperate` · 真网关无头联调（已完成）

**前置：** B 把代码推到 `network-b3`。不需要 B 合并，也不需要设备。

**做法：** 用独立工作区 `D:\1.Studying\AndroidStudio\Light-Chase-b3` 检出 B 的分支，只当作"可编译、可启动的服务器"；我的分支保持干净，不含 B 的任何代码。

**依赖 B 的什么（逐项，这才是耦合面）**

只在运行期依赖下面七项**线上可见的行为**；**不依赖**他的源码结构、内部实现、测试和工作区布局（他重写 `LobbyServer` +1219 行不影响我）。

| # | 依赖项 |
|---|---|
| 1 | **房间阶段机**：`LOBBY → COUNTDOWN`（90 拍 = 3 秒）`→ RUNNING → FINISHED`，两人都 `READY` 才开始 |
| 2 | **逐角色 `SNAPSHOT`**：15 Hz 下发；`tick` 严格递增但**会跳号**（实测 0,1,2,4,6） |
| 3 | **角色隔离**：警察收到的 `view.thief` 恒为 `null`，小偷才有 `ThiefPrivate`；小偷隐身后警察的 `opponent` 变为 `null` |
| 4 | **控制事件 ACK**：`PENDING / SUCCEEDED / FAILED / TIMED_OUT` 四态；`LEAVE_ROOM` 在 `RUNNING` 时先转成 Departure、**下一步才结算** |
| 5 | **结果投递顺序**：`FINISHED` 先于 `RESULT`；**终局快照可缺省** |
| 6 | **HELLO 校验 `mapHash` / `configHash`**，不匹配属**致命**错误（`MAP_MISMATCH` / `CONFIG_MISMATCH`） |
| 7 | **端点与握手**：`ws://<host>:8080/game`（路径必须是 `/game`，否则 `BAD_MESSAGE`）；心跳缺失 3 秒 → `SUSPECT` |

**结果：**

| 项 | 实测 |
|---|---|
| B 的分支在 Windows 上编译 | ✅ `checkJvm` + `:server:installDist` 通过（他在 macOS 开发） |
| B 的回归 | **435 项，0 失败** |
| 探针：真服务器 + 两个真网关跑完整一局 | ✅ 绿 |

**探针记录的真实回调顺序**（这是我界面依赖的全部假设）：

```
SESSION null → CONN CONNECTING → HANDSHAKING → HELLO PENDING
SESSION <id> → HELLO SUCCEEDED → JOINING → JOIN_ROOM SUCCEEDED → CONNECTED
ROOM LOBBY → ... → ROOM COUNTDOWN
ROOM RUNNING match=<id>
VIEW tick=0,1,2,4,6 (15 Hz，tick 有跳号)
CONTROL LEAVE_ROOM PENDING
ROOM FINISHED → VIEW tick=8（终局快照）→ RESULT QUIT → LEAVE_ROOM SUCCEEDED
SESSION null → CONN CLOSED
```

**由此确认 / 修正的六件事：**

1. `onSession` 先于第一个 `onRoom` —— 我的 `resetSession` 时机正确。
2. 没有快照能早于 `RUNNING`；`tick` **严格递增但会跳号**（15 Hz 快照），我的单调过滤不会误判。

## 5. 界面与数据口径

1. **页面唯一来源**：页面只从 `RoomState.phase` 与 `ConnectionStatus.state` 推导，客户端不保存第二份阶段。
2. **单位与时间**：世界单位是格，原点左下，格心 `(x+0.5, y+0.5)`；线上时间单位是秒，内部是 30 Hz 的 tick；`tickRate`／`countdownTicks`／`durationTicks`／`interactTicks` 一律读 `RuleConfig`。
3. **视角尺寸**：世界固定 `128/9 × 8`（`16:9`，中心宽 14.22 格、高 8 格）。这是 A 的视野矩形与 C 的相机共同依赖的值，任何一方单独改都会导致“看到的世界不一样”。
4. **空值与隐藏**：对手不可见时 `opponent` 必须是 `null`，客户端**不做淡出、不做插值**，第一帧就消失；`MatchResult.winner` 可以为 `null`，此时结果页显示 `WINNER  NONE (both players left)` 与 `YOUR RESULT  NO DECISION`，不当成异常。
5. **权限**：`ACCESS_LOCAL_NETWORK` 只在 LAN 模式申请，未授权不创建 socket，失败原因要能区分权限/地址/服务器。
6. **快照顺序**：只接受严格更新 `tick` 的快照；同一 `matchId` 内插值，换 `matchId` 立即清空历史。
7. **`SUSPECT` 不是断线**：契约把它定义为 3 秒无 PONG。此时会话与最后一帧仍有效，必须留在对局页，只在角落显示网络告警；只有 `CLOSED`／`DISCONNECTED` 才丢弃画面回连接页。
8. **契约字段的使用边界**：`PlayerView`／`RoomState`／`ThiefPrivate`／`InteractionView` 里每个字段都要么被渲染、要么说明为什么不用：

| 字段 | 用不用 | 理由 |
|---|---|---|
| `serverTimeMs` | 不用 | V1 用本地时钟做插值，不做时钟同步 |
| `ackInputSeq` | 不用 | 用于对账；V1 不显示延迟与丢包补偿 |
| `requiresRelease` | 不用（但显示后果） | 是否强制松手由服务端判定；客户端通过 `blockedReason=RELEASE_REQUIRED` 呈现给玩家 |
| `deliveredMaterialIds` | 不用 | 界面只显示交付数量；具体是哪三件由 `originStatus` 表达 |
| 其余字段 | 全部使用 | 见 §3.1 与 §4 |

## 8. 风险与环境

0. **提交规则**：未经用户明确同意，不执行 `git add` / `git commit` / `git push`；每步先交付未提交改动与说明。
1. **仓库路径必须纯 ASCII**，否则 AGP 直接拒绝；课程资料可以放在中文目录，代码不行。
2. **JDK 必须 17 以上**（本机用 21 验证）：本机默认 JDK 25 会让 Gradle 无法启动，需显式设置 `JAVA_HOME`。
3. **Gradle 缓存固定在 D 盘**（`GRADLE_USER_HOME`），不往 C 盘写。
4. **`git push`／`fetch` 可能卡住或被重置**：其中一类是 HTTP/2 引起，仓库内 `git config http.version HTTP/1.1` 可解决（该配置不随仓库提交）；另一类是网络本身不通，表现为 DNS 能解析但 TCP 连不上，只能重试或等网络恢复。
5. **模拟器不稳定**：进程活着但 `mCurrentFocus=null`、`screencap` 挂起，需强杀 `qemu-system-*` 并清理 `.avd` 下的锁目录。
6. **视口尺寸是三方共同依赖**：`128/9 × 8` 不能单方面修改。
7. **截图与视频要等界面定稿**：提前拍摄会因合并改动返工。
