## 4. 步骤 4 · `Available · Individual` · 真实网关与局域网权限

### 4.1 本步范围

只做传输层接线、权限、插值、网络提示与代码拆分；不做真实快照渲染。

### 4.2 改动

| 文件 | 类型 | 说明 |
|---|---|---|
| `client-core/.../LightChaseApp.java` | 修改 | 双网关切换、权限前置、回调队列、网络提示；抽出后本类 746 行 |
| `client-core/.../WorldRenderer.java` | 新增 | 从 `LightChaseApp` 抽出地图/光束/角色/小地图（186 行） |
| `client-core/.../ViewInterpolator.java` | 新增 | 100 ms 插值，纯 Java |
| `client-core/.../LanPermission.java` | 新增 | 局域网权限的平台抽象 |
| `android/.../AndroidLauncher.java` | 修改 | 注入替身与真实网关工厂；API 37 起申请 `ACCESS_LOCAL_NETWORK` |
| `client-core/src/test/.../ViewInterpolatorTest.java` | 新增 | 6 项插值测试 |

### 4.3 校验内容

- 每次 LAN 连接**新建**网关实例，旧 socket 与监听器不会串入新会话。
- 切换 `MODE` 时关闭旧传输并清空会话，避免两个传输同时回调。
- `ACCESS_LOCAL_NETWORK` 在**创建 socket 之前**校验；未授权时不建连接，提示写明是权限问题，不报成服务器宕机；API < 37 视为不需要。
- 网关工厂返回 `null` 时有守卫，不会把 `null` 当传输使用。
- 回调统一入队，渲染线程消费；插值窗口 100 ms。
- 对手不可见时**不插值**，第一帧即消失；换 `matchId` 清空插值历史。
- 旧传输在**四处**都会被关闭：错误路径、切换模式、重连前替换网关、`dispose`。
- 页面状态清零只有一处实现（`resetSession`），帧丢弃与插值清理成对（`dropFrame`）。
- `SUSPECT` 与 `CONNECTED` 都视为会话存活（`ConnectionStates.isSessionAlive`）；只有 `CLOSED`／`DISCONNECTED` 才丢弃当前帧并回连接页。

### 4.4 测试结果

`checkJvm` 195 项通过；`ViewInterpolatorTest` 6 项。

### 4.5 已知边界与下一步

`WebSocketClientGateway.error()` 只发 `onError`，**不改变 `ConnectionStatus`**（`WebSocketClientGateway.java:145`；行号基于当前 `main`，`codex/network-b3` 已重写该文件但行为未变）。客户端因此必须自行关闭传输，否则状态停在 `CONNECTING`，客户端的 `ALREADY_CONNECTED` 守卫会把重连永久锁死。建议 B 在 `error()` 内落终态，或在契约 §12.1 写明。设备侧表现（权限弹窗、模式按钮、网络提示）本步未在模拟器上验证。

### 7.4 由此修正的客户端问题

| 问题 | 处理 |
|---|---|
| 对局中无法退出（对局页没有退出入口，只能切后台） | 新增 `QUIT MATCH`：发 `leaveRoom()` 后**保持连接**等 `GAME_OVER`，5 秒未确认则恢复并提示 |

| 替身对局中退出直接断开、不发结果 | 改为先以 `QUIT` 结算再断开 |
| 替身把 `QUIT` 的赢家恒定为 `POLICE` | 改为"退出者的对手获胜"，警察退出则小偷赢 |

### 7.6 这一步证明了什么

证明的是**协议与时序**：真服务器发的序列与我的状态机假设一致，退出与回大厅链路成立。

**没有证明**：画面（像素、触控、双机同房）——那需要设备。
