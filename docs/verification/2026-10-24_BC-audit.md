## 2. [P2] 网关没有防止快照 tick 回退或校验包络/body 的 matchId

位置：`client-network/src/main/java/com/lightchase/network/WebSocketClientGateway.java:292`。

SNAPSHOT 分支只检查 running 和包络 matchId，随后直接 onView；不保存最高 tick，也不比较 PlayerView.matchId。独立真实 WebSocket 探针发送递增包络 seq、tick=100 后再发送 tick=90，两帧均交给界面；包络 matchId=m、body.matchId=other-match 的快照也被交给界面。

影响：旧位置、旧可见性和错误局数据可以覆盖新视图，不满足契约 §10、§12.3 的业务校验要求。

修复及回归：保存每局最高已接收 tick，按契约处理同 tick 的首次终局更新；验证包络/body 局号、自身身份与角色等关联；新局重置校验状态。增加高 seq/低 tick、重复 tick、局号不一致及跨局回归。

## 3. [P2] ROOM_STATE 无 revision、房间、资源和结束阶段保护

位置：`client-network/src/main/java/com/lightchase/network/WebSocketClientGateway.java:275`。

ROOM_STATE 直接覆盖 running/matchId 并回调，没有验证房间和资源是否属于当前连接，没有记录 revision，也没有结束局的阶段保护。探针确认 revision 10→9 会回调，roomId=WRONG/mapHash=wrong-hash 也会回调；收到 GAME_OVER 后再发送同局更高 revision 的 RUNNING，网关重新接受该局 SNAPSHOT。

影响：界面可能回到旧房间或已结束对局，且该分支清除 reportedResultId，破坏结束幂等性。WireCodec 只验证结构，不能替代这层状态机校验。

修复及回归：验证握手身份、房间、资源、成员、revision 及合法阶段转移；保存已结束局状态，禁止该局重入 RUNNING。覆盖错误房间/哈希、revision 回退、结算后旧状态及新局合法迁移。

## 4. [P2] SUSPECT 期间提交的输入会在恢复后自动重放

位置：`client-network/src/main/java/com/lightchase/network/WebSocketClientGateway.java:352`；关联 `pulse():216`。

进入 SUSPECT 时虽清零，但 submitInput 在判断 suspect 之前仍更新 currentFrame 和 lastInput。C 按任务书每帧调用 submitInput，会在疑似断线期重新填入移动/按住状态。恢复后下一次 pulse 直接发出它，没有要求重新操作。

独立探针：无包 3000ms → SUSPECT → submitInput(1,0,true,false) → 合法房间包恢复 → pulse。服务端实际收到 `moveX=1.0, interactHeld=true`。

修复及回归：SUSPECT 时不缓存有效操作；恢复时重新清输入并要求符合契约的重新操作，避免仍按住的交互自动继续。增加按住、移动、drop、租约和恢复边界测试。

## 5. [P2] 结果去重仅比较 resultId，未锁定一局的首个结果

位置：`client-network/src/main/java/com/lightchase/network/WebSocketClientGateway.java:297`。

代码只比较 reportedResultId 和新 resultId。探针对同一 matchId 先发送 r1，再发送内容不同的 r2，onResult 被调用两次。相同 resultId 内容变化也没有内容比较或诊断。

影响：服务端缺陷或重复投递异常可让同一局重复结算、改变展示；不满足唯一结果和“保留首个并记录冲突”的契约。

修复及回归：按 matchId 保存首个完整结果；重复一致结果只确认；内容不同或另一 resultId 的同局结果不覆盖、不再次回调，并记录受控诊断。覆盖同 ID 同内容、同 ID 异内容、异 ID 同局及合法第二局。

## 6. [P2] 服务端未实现 3 秒 SUSPECT 与恢复广播

位置：`server/src/main/java/com/lightchase/server/LobbyServer.java:847`、`:918`。

RoomPlayer.connection 永远写死为 CONNECTED，expire 只处理 5 秒关闭，没有 3 秒状态、revision 更新或恢复广播。独立双 WebSocket 探针将服务端可控时间推进到 3000ms，保持第一位玩家无新消息，再由第二位玩家触发房间广播，第一位玩家仍显示 CONNECTED。

影响：另一端无法在 3 秒时看到对手网络异常，B5 验收要求未落地。

修复及回归：记录每会话健康状态；3 秒切 SUSPECT 并广播，合法新包恢复 CONNECTED 并广播；5 秒确认断开，保持正常结局优先级。覆盖 2999/3000/4999/5000ms、旧包不续期、恢复与同拍双方断线。

## 7. [P2] B7 协议示例与实际 Codec/DTO 不一致

位置：`server/B7_实现与交接.md:331`、`:374`、`:415`。

将文档 JSON 逐条交给当前 WireCodec，以下三份均返回 BAD_MESSAGE：

- RUNNING 的 ROOM_STATE：包络 matchId 非 null；契约要求 ROOM_STATE 包络始终为 null，局号放在 body。
- SNAPSHOT：使用不存在的 visibleMaterials、marked、heading 等字段，缺少 PlayerView 的多个必填字段，ActorPose 也不匹配。
- GAME_OVER：缺少 marks、deliveredCount、finalTick。

此外，文档 `gateway.submitInput(moveX, moveY, interactHeld, dropPressed)` 不符合现有唯一签名 `submitInput(InputFrame)`。

影响：C 照交付示例实现或测试会遇到协议拒绝或编译错误，B7 的示例交付不能判合格。

修复及回归：从真实 contracts DTO 和 Codec 生成示例，修正调用签名，并让文档示例进入 Codec 回归。同步清理 README、03/05/08 和 B5–B7 之间互相冲突的完成度描述；311 项现有测试通过不能替代未完成的联合验收。
