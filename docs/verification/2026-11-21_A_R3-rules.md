## 3. 已实现的规则

| 功能 | 实现要点 |
|---|---|
| 独立瞄准 | 警察 `aimRad` 与 `headingRad` 分离；null 保持上次；移动不改手电；小偷 aim 必须 null；角度 `[0,2π)` |
| 移动 | 最后命令决定方向；斜向归一化；撞墙滑动；加速只改有效速度；移动尝试取消交互 |
| 双道具槽 | 两槽独立实例；同类可共存；满槽地面保留；指定槽独立消耗 |
| 加速/光照 | 可并存；同类有效时 `EFFECT_ACTIVE` 且不扣槽；倍率真实影响速度/`BeamView.range`；到期恢复 |
| 护盾 | 清 `beamProgress`、取消交互、不增减 marks；`invisibleUntil=max(tick+shieldTicks, 原截止)`；原免疫截止不延后 |
| 保护判定 | 先真隐身、再免疫；只接尚未到期的原免疫尾段；新标记清除护盾展示 |
| 两角色交互 | 警察可拾自己的道具、不能拾卡/解锁/进入；小偷可拾任务物资/道具/卡、交付、撤离、解锁、进入 |
| 候选与阻塞 | 过滤角色/状态/容量/卡匹配/距离/射线后按距离、同距按 `targetId`；精确 `InteractionBlock` 原因 |
| 门禁卡 | 小偷独立单卡槽；已有卡拒绝第二张；警察不能拾；满道具槽不影响拾卡 |
| 单向暗道 | 两通道/四端点；入口解锁、松开重按才进入；出口无候选；警察不能使用；本局永久解锁 |
| 传送 | `PORTAL_STARTED` 每趟一条；双方同一 `TransitView`；警察普通 `opponent=null`；过程禁移动/交互/用道具；落地清旧输入并恢复地表 |
| 动作结果 | 每玩家 actionId 去重 + 128 条缓存；失败码 `EMPTY_SLOT`/`ITEM_INSTANCE_MISMATCH`/`ROLE_FORBIDDEN`/`IN_TRANSIT`/`EFFECT_ACTIVE`/`STALE_ACTION`/`MATCH_ENDED` |
| 视图权限 | 警察 `thief=null`；地面道具/卡公开；库存/卡槽/保护/任务物资私有；光球是唯一公开传输例外 |
| 结局 | 超时 > 抓捕 > 撤离；正常结局优先于离开；单/双方离开；abort/幂等 |
| 新局 | 新引擎实例从 tick=0、空库存/卡/效果/光球、锁定通道开始 |
| 配置校验 | 规则全参数、`mapVersion=2`、2 通道/2 卡、四端点互异、卡-通道配对、ID 唯一、可站立/按角色可达 |

## 6. 严格编解码兼容性

`V2WireCompatibilityTest` 用真实的 `V2WireCodec` 对以下内容做 encode→decode→body 往返：

- 生产 `V2DataFiles.bundled()` 的警察/小偷初始视图和首步视图；
- 传送中的双方视图；
- `PORTAL_STARTED` 公开事件；
- `ACTION_RESULT` 成功回执。

结果 3 项全部通过。它验证的是 A 产出与 B 的严格字段约束一致，不代表 B 的服务端/网关已经接入 v2。

完整的创建/输入/视图/动作结果示例见 [A 部分 v2 引擎接入示例](../development/15_A_v2引擎接入示例.md)。

### 给 B

- 入口：`new V2EngineFactory().create(map, rules, init)`；`map`/`rules` 直接使用 `V2DataFiles.bundled()` 的类型。
- `step()` 返回 `StepResult`，`viewFor(playerId)` 返回 v2 `PlayerView`；`serverTimeMs` A 返回 0，B 填真实时间。
- `ackInputSeq` A 填该玩家已消费的最大输入序号，B 可原样使用。
- B 仍需完成：v2 握手/会话、INPUT/USE_ITEM/ACTION_RESULT/PUBLIC_EVENT 收发、动作去重/超时、快照策略。
- `game-core/build.gradle` 的 `client-network` 依赖是 test-only，B 不需要在自己的生产路径引用。

### 给 C

- 警察 `aimRad` 是独立输入；C 的 “按住 AIM 按钮拖动瞄准”只需生成合法 `[0,2π)` 角度。
- 视图字段：`inventory` 恰 2 项（空槽 null）、`effects` 只含本人、`interaction` 在顶层、`portals` 全量、`transits` 至多一条、`thief` 仅小偷。
- 小地图/光球/卡槽的绘制由 C 负责；A 只保证权限和权威坐标，不在 UI 判定成功。
