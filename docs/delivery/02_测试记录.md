# 测试记录

记录**这一支（C · Android 客户端）**在交接时的测试规模、覆盖范围、复现方式，以及**没有自动化**的部分。

> 数字会随后续提交变化。本文的数字取自 `feat/android-ui-flow` 分支的一次 `checkJvm` 全绿结果。

---

## 一、怎么复现

```bash
./gradlew.bat checkJvm            # 全部 JVM 测试
./gradlew.bat :android:assembleDebug
./gradlew.bat :server:installDist
```

`checkJvm` 是仓库根 `build.gradle` 里注册的聚合任务，等价于各模块的 `test`。
成功时最后一行是 `BUILD SUCCESSFUL`；明细在 `*/build/test-results/test/TEST-*.xml`。

## 三、这一支测过什么（有测试为证）

| 能力 | 证据 |
|---|---|
| 五页状态机（连接/大厅/倒计时/对局/结算） | `FakeGatewayTest` 走完整流程 |
| 双网关（离线 + 真实）与运行时切换 | `FakeGatewayTest` + `ConnectionStatesTest` |
| 对局中退出不立刻断开 | `MatchQuitTest`，含重放真服务器事件序 |
| 界面读的字段与引擎一致 | `EngineFieldStoryTest`（真实 `V1EngineFactory`） |
| 正式图切换只是改一个常量 | `FormalMapReadinessTest`，含指错路径立刻失败 |
| 触摸与插值 | `TouchControllerTest`、`ViewInterpolatorTest` |
| 多比例不变形 | `ViewportFitTest` |

## 四、没有自动化的部分（必须人工）

| 项 | 为什么不能自动 | 什么时候做 |
|---|---|---|
| 真机触控、多指、手势条遮挡 | 需要真实设备；JVM 无法创建 GL 上下文 | 真机到位后 |
| 双机同房画面一致 | 需要两台设备同一次对局 | 同上 |
| 真实局域网权限弹窗 | 需要 API 37+ 设备 | 同上 |
| 切后台/回来的表现 | 需要前台的系统行为 | 同上 |
| 演示视频与截图 | 界面定稿后拍摄 | 步骤 7-W |

这些在 `03_已知问题.md` 里按条目跟踪，不重复列。

## 五、怎么读失败

1. 先看 `*/build/test-results/test/TEST-*.xml` 里的 `<failure message="...">`
2. 断言消息是**描述界面后果**的（例如 `the origins line grows one material at a time`），照着改对应控件
3. 若失败来自 `game-core`，那是 A 的规则变了，先找 A 确认再改客户端

> `client-core` 有一条只用于测试的依赖：`testImplementation project(':game-core')`。
> 运行期客户端**不依赖规则引擎**，只认识 `PlayerView`——APK 里不会有引擎代码。
