# 启动说明

本文件回答三个问题：**要装什么、怎么起、起不来时看哪里**。

> **先说清楚这份说明的适用范围**
>
> `main` 已经包含 B 的联机实现（PR #2，`d12eff0`）：倒计时、逐角色快照、结果投递都在，
> **服务端可以直接开一局**。所以本文只分两条路径，**先看你要做哪一件事**。

| 你想做的事 | 走哪条路 | 需要服务器吗 |
|---|---|---|
| 看一眼画面、走两步、点按交互 | **A 离线演示** | 不需要 |
| 真正打一局（倒计时、快照、结算） | **B 完整对局** | 需要（本仓库 `main` 即可） |

---

## 一、环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| JDK | **17 以上**（本机用 21 验证）；编译目标固定 17 | `JAVA_HOME` 指向 JDK 17+；版本过低会在 Gradle 配置阶段直接失败 |
| Android SDK | compileSdk / targetSdk **37**，minSdk **26** | 37 以下没有 `ACCESS_LOCAL_NETWORK` 权限，代码按"不需要"处理 |
| Gradle | 用仓库自带 wrapper（`gradlew.bat`），不要用本机 Gradle | wrapper 固定版本并校验 `distributionSha256Sum` |
| 路径 | **仓库放在纯 ASCII 路径下** | 中文路径会让 Android 资源合并报错 |

首次构建（会下载依赖，耗时较长）：

```bash
./gradlew.bat :android:assembleDebug
```

产物：`android/build/outputs/apk/debug/android-debug.apk`

## 二、路径 A：离线演示（最省事，推荐先跑这条）

不需要服务器、不需要另一台设备。离线替身（`FakeGateway`）在客户端进程内模拟一整局。

```bash
# 1. 构建
./gradlew.bat :android:assembleDebug

# 2. 装到设备/模拟器
adb install -r android/build/outputs/apk/debug/android-debug.apk

# 3. 打开应用 → 连接页 → 点 MODE 切到 OFFLINE → 点 CONNECT
```

进入后的流程：大厅 → 点 `READY` → **3 秒倒计时** → 对局（摇杆移动、`HOLD` 按住交互、`DROP` 丢弃）。

**对局怎么结束**（三种，别搞混）：

| 方式 | 操作 | 结果 |
|---|---|---|
| 脚本胜利 | 连接页点 `SCENARIO` 切到 `POLICE_WIN` 或 `THIEF_WIN`，再开局 | 走到对应胜利 → **结算页** |
| 超时 | `SCENARIO` 保持 `NORMAL`，对局跑满 12 秒 | 按 `TIMEOUT` 结算 → **结算页** |
| 主动退出 | 对局中点 `QUIT MATCH` | **回到连接页**，底部显示一句结果说明（不会出现结算页） |

在结算页点 `BACK TO LOBBY` 回大厅。

> 最后一条容易误会：主动退出时服务器发完结果就关闭会话，客户端没有任何对局残留，
> 所以结果只能以一句话的形式留在连接页。这是契约决定的，不是缺陷。

> 连接页的 `SCENARIO` 还能复现失败流程：`CONNECT_FAIL`、`ROOM_FULL`、`ROLE_TAKEN`、`INVALID_PHASE`，
> 方便在没有服务器的情况下看错误提示。

> 离线替身**不实现游戏规则**：它按剧本给出标记、交付、保护状态，用于验证界面与流程。
> 真实规则在 A 的引擎里，只有走路径 C 才会用上。

## 三、路径 B：完整对局（需要服务器）

```bash
# 1. 起服务端（默认 8080，也可传端口：server.bat 9000）
./gradlew.bat :server:installDist
server/build/install/server/bin/server.bat

# 看到这行即为就绪：
# Light Chase B7 server listening on ws://0.0.0.0:8080/game
```

然后：

```bash
# 2. 装客户端（同上）
adb install -r android/build/outputs/apk/debug/android-debug.apk

# 3. 连接页 → MODE 切到 LAN → HOST 填地址 → ROOM 填房间号 → CONNECT
```

**HOST 填什么**

| 场景 | HOST |
|---|---|
| 模拟器连本机服务端 | `10.0.2.2`（模拟器访问宿主机的固定地址，客户端的默认值） |
| 真机连同一 Wi-Fi 下的电脑 | 电脑的局域网 IP，例如 `192.168.1.23` |
| 同一台机器上跑 | `127.0.0.1` |

**ROOM** 默认 `DEMO`，两端必须填**同一个**。

这条路径能验证：连接状态机、握手、进房、准备、**倒计时、对局、快照、结算**、错误码、`NET <STATE>` 提示。
只有**画面**（像素、触控手感、双机一致性）仍需设备，见 `03_已知问题.md`。

## 四、局域网权限

| 项 | 内容 |
|---|---|
| 权限名 | `android.permission.ACCESS_LOCAL_NETWORK` |
| 何时申请 | LAN 模式下点 `CONNECT` 时；**未授权前不会创建 socket** |
| API < 37 | 视为不需要（该权限在 37 才引入），不会弹窗 |
| 被拒绝 | 连接页显示 `ACCESS_LOCAL_NETWORK <状态> - grant it, then connect again`，不会静默失败 |

## 五、起不来时看哪里

界面底部有一行状态（左边 `ERROR ...` 优先于普通提示）。按这个表对号：

| 现象 | 含义 | 怎么办 |
|---|---|---|
| `ERROR ALREADY_CONNECTED - a session already exists` | 上一次连接没关干净 | 点 `MODE` 切一次（会关闭旧传输），或重启应用 |
| `ERROR INVALID_ADDRESS - port must be 1-65535` | 端口填错 | 改端口号 |
| `ERROR INVALID_ADDRESS - room id must not be empty` | 房间号为空 | 填一个，例如 `DEMO` |
| `ERROR ACCESS_LOCAL_NETWORK ...` | 权限未授予 | 授予后重新 `CONNECT` |
| `ERROR LAN gateway unavailable` | 网关工厂返回 null（构建问题） | 重新构建；这是不应该出现的状态 |
| `ERROR MAP_MISMATCH` / `CONFIG_MISMATCH` | 客户端与服务端读的不是同一份地图/规则 | 见 `03_已知问题.md` **第 2 条**，别单方面改图 |
| `ERROR INVALID_PHASE` | 请求的时机不对（例如对局中发 `SET_READY`） | 回到大厅再操作；这是正常的阶段校验 |
| `NET SUSPECT` | 3 秒没收到心跳回应，但会话还活着 | 游戏继续；这是提示不是断线 |
| 一直停在 `CONNECTING` | 地址/端口不通，或服务端没起 | 先用 `telnet <host> <port>` 确认端口可达 |
| 界面空白、按钮点不动 | 资源没打进 APK | 确认 APK 里有 `assets/maps/*.json` 与 `assets/rules/v1.json` |

## 六、最小自检（三条命令）

```bash
./gradlew.bat checkJvm            # 全部 JVM 测试
./gradlew.bat :android:assembleDebug
./gradlew.bat :server:installDist
```

三条都成功，说明环境、测试、客户端打包、服务端发行包都正常。
数量与含义见 `02_测试记录.md`。
