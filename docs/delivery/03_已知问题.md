# 已知问题

按**影响**分三级。每条写清：现象 → 原因 → 影响范围 → 临时办法 → 归属。

- **A 级**：会挡住"能跑完一局"或交付，必须解决
- **B 级**：不挡流程，但会让人误解或体验变差
- **C 级**：文档/整洁问题

---

## A 级

### 1. 本分支服务端不能开局

| 项 | 内容 |
|---|---|
| 现象 | `SET_READY(true)` 返回 `INVALID_PHASE`（"S0 skeleton: countdown and matches are not implemented yet"），对局永远起不来 |
| 原因 | `main` 上的 `LobbyServer` 是 S0 骨架，只做握手与大厅 |
| 影响 | 走本分支服务端时只能验证握手/进房/错误码；完整对局必须用 B 的 `network-b3` |
| 临时办法 | 路径 A（离线演示）看画面；路径 C（B 的分支）打完整对局，见 `01_启动说明.md` |
| 归属 | **B**（已在其分支实现，等合并） |

### 2. 正式图尚未切换

| 项 | 内容 |
|---|---|
| 现象 | 三方读的仍是 `maps/test-room.json`；切到 `maps/v1.json` 后 `mapHash` 会变 |
| 原因 | `mapHash` 参与 HELLO 校验，`MAP_MISMATCH` / `CONFIG_MISMATCH` 是**致命**错误，任一方单独改都会导致**连不上** |
| 影响 | 现在不能单方面换图；正式图的画面效果还没在真实对局里看过 |
| 临时办法 | 客户端侧已就绪：改 `ClientAssets.MAP` 一行即可；**等三方同一次提交** |
| 归属 | **A**（冻结 v1 + 基准 hash）、**B**（服务端改图）、**C**（改常量），三方同时 |

> 切换清单与实测差异见进度报告「步骤 6-AC」。

## B 级

### 3. 真实网关的 `error()` 不落连接终态

| 项 | 内容 |
|---|---|
| 现象 | 连接级错误发生时，网关只发 `onError`，`ConnectionStatus` 仍停在 `CONNECTING` |
| 原因 | `WebSocketClientGateway.error()` 的实现如此 |
| 影响 | 若客户端不自行关闭传输，会卡在 `CONNECTING`，并被自身的 `ALREADY_CONNECTED` 守卫锁死，再也连不上 |
| 临时办法 | **客户端已兜底**：收到错误后自己关闭传输（有测试守着） |
| 归属 | **B**（建议在 `error()` 内一并落终态，或在契约 §12.1 写明） |

### 4. 连接状态字符串两处各存一份

| 项 | 内容 |
|---|---|
| 现象 | `client-core` 的 `ConnectionStates` 与 `client-network` 各有一份状态字面量 |
| 原因 | 两侧独立实现，没有从契约生成 |
| 影响 | 改一处忘另一处会导致 `NET <STATE>` 显示不一致 |
| 临时办法 | 目前两侧取值相同；改动时**两处一起改** |
| 归属 | 建议由契约集中生成 |

### 5. `returnToLobby` 可随时发送，`resultId` 可能为 null

| 项 | 内容 |
|---|---|
| 现象 | ① 结算页的 `BACK TO LOBBY` 发 `RETURN_LOBBY`，但 `resultId` 可能为空；② **`ESC` 键在任意页面都会发** `RETURN_LOBBY`（`LightChaseApp:136`），没有页面判断 |
| 原因 | 契约未限制时机（见 `08 §7` 已知偏差表）；`ESC` 是桌面调试用的快捷入口，Android 上没有这个键 |
| 影响 | 服务端需容忍"非结算页的 `RETURN_LOBBY`"和空的 `resultId`，否则可能回 `INVALID_PHASE` |
| 临时办法 | 手机端不会触发 `ESC`；服务端按契约容忍这两种情况 |
| 归属 | 待契约 R3 收敛；若要收紧，客户端加一句页面判断即可 |

### 6. API < 37 的权限行为未经真机验证

| 项 | 内容 |
|---|---|
| 现象 | `ACCESS_LOCAL_NETWORK` 在 API < 37 被视为"不需要"，不弹窗 |
| 原因 | 该权限在 37 才引入；代码按版本判断 |
| 影响 | 若低版本真机上实际仍有网络限制，会表现为"连不上但无提示" |
| 临时办法 | 真机上先看 `NET` 状态；必要时用 `telnet <host> <port>` 确认 |
| 归属 | **C**，需真机 |
