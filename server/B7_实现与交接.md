## 二、服务端打包与分发运行机制

### 1. 打包命令与产物路径
在工程根目录 `Light-Chase` 下执行 Gradle 打包任务：
```sh
sh ./gradlew :server:installDist
```
该任务利用 Gradle `application` 与 `distribution` 插件，在 `server/build/install/server` 下生成完全自包含、可脱离 Gradle 直接运行的绿色分发包：
```text

├── bin/
│   ├── server        # POSIX Shell 启动脚本 (macOS / Linux)
│   └── server.bat    # Windows CMD 批处理脚本
├── lib/              # 运行所需的全部依赖 jar（包含当前项目各模块及第三方库）
│   ├── server-0.1.0-SNAPSHOT.jar
│   ├── contracts-0.1.0-SNAPSHOT.jar
│   ├── game-core-0.1.0-SNAPSHOT.jar
│   ├── game-data-0.1.0-SNAPSHOT.jar
│   ├── client-network-0.1.0-SNAPSHOT.jar
│   ├── Java-WebSocket-1.6.0.jar

│   └── slf4j-simple-2.0.16.jar
├── THIRD_PARTY_NOTICES.md
```

### 2. 独立分发与运行方式
分发时只需将 `server/build/install/server` 目录整体拷贝至目标机器（目标机器仅需具备 JRE 17+ / JDK 21），即可直接运行脚本启动服务端：
```sh
# macOS / Linux:
./bin/server [port]

# Windows:
.\bin\server.bat [port]
```
无需安装 Gradle，无需拉取源码，脚本会自动组装 `CLASSPATH` 并启动 `com.lightchase.server.ServerMain`。

## 三、可配置端口与优雅启停

### 1. 端口配置优先级与校验规则
`ServerMain.parsePort` 实现了严格的层级优先级配置与受控校验：
1. **最高优先级：命令行参数 `[port]`**
   - 示例：`./bin/server 9090` 或 `sh gradlew :server:run --args="9090"`；
   - 若提供了命令行参数，优先采用该参数；
   - 若参数数量大于 1，立即抛出受控异常：`IllegalArgumentException("Usage: server [port], port must be 1..65535")`。
2. **次优先级：环境变量 `PORT`**
   - 当无命令行参数时，检查 `System.getenv("PORT")`；
   - 示例：`PORT=8090 ./bin/server`；
   - 自动去除前后空白符（`trim()`）；
   - 若环境变量格式非法或数值越界，抛出受控异常：`IllegalArgumentException("Usage: server [port] or PORT env var, port must be an integer in 1..65535 (PORT=...)")`。
3. **缺省兜底：默认 `8080`**
   - 当既无 CLI 参数，又无 `PORT` 环境变量（或环境变量为空字符串）时，自动采用默认端口 `8080`。
4. **端口合法范围校验**：
   - 端口数值必须在 `1..65535` 范围内，任何 `< 1`、`> 65535` 或非整数字符串均被拒绝并输出 Usage 提示。

### 2. 优雅启停（Graceful Shutdown）
- **JVM ShutdownHook 注册**：
  在服务器启动前注册钩子线程：
  ```java
  Runtime.getRuntime().addShutdownHook(new Thread(() -> {
      try {
          log.info("Shutdown signal received (SIGINT/SIGTERM), gracefully shutting down LobbyServer...");
          server.shutdown();
          log.info("LobbyServer graceful shutdown complete.");
      } catch (InterruptedException e) {
          Thread.currentThread().interrupt();
          log.warn("LobbyServer shutdown interrupted.");
      }
  }, "lightchase-shutdown-hook"));
  ```
- **资源安全回收流程**：
  1. `stopping.compareAndSet(false, true)`：原子标记停机状态，后续网络事件与定时轮询不再受理；
  2. `logic.shutdown()`：停止接收新调度任务，并等待最多 2 秒以执行完当前正在流转的业务 step，若超时则调用 `logic.shutdownNow()`；
  3. `stop(1000)`：底层 `WebSocketServer.stop(1000)` 依次向所有已连接的客户端发送状态码 `1001`（Going Away / Server Shutdown）并关闭底层 TCP 套接字通道，释放端口占用；
  4. 保证 `server.shutdown()` 的幂等性，多次重复调用安全无害。

## 四、规范受控诊断日志（Diagnostic Logging）

### 1. 契约规范与敏感数据隔离原则（`02_接口契约.md` 第 11 节）
契约严格要求：
> “服务端日志只记录 `roomId`、`matchId`、`seq`、错误码、状态跃迁和受控诊断；客户端正常日志不输出对手隐藏位置。调试全状态只可在服务端受控测试中使用，不加入发布消息或 UI 开关。”

为此，服务端日志体系确立了**绝对的敏感数据隔离铁律**：
- **禁止记录**：对局中的任何玩家绝对坐标（`x`、`y`）、小偷的隐蔽状态、未授权私有状态（如候选物资详情、携带物私有进度）、或引擎内部的未过滤数据；
- **允许记录**：
  - 会话与通道事件：连接打开、断开码（1000/1001/1008 等）、断开原因、远端地址（带 safeRemote 保护）；
  - 握手与校验：协议版本、`mapHash`、`configHash` 校验结果；
  - 状态跃迁：`LOBBY -> COUNTDOWN -> RUNNING -> FINISHED -> LOBBY`、准备状态变更、角色分配；
  - 限流告警：输入超过 60/s、控制超过 10/s；
  - 背压告警：出站控制队列达到 64 缓冲上限；
  - 受控错误：错误码（`BAD_MESSAGE`、`INVALID_PHASE`、`ROLE_TAKEN`、`STALE_MATCH` 等）、关联 `seq`、`requestId`、`roomId`、`matchId`。

## 七、给 C 侧（Android/UI）的完整接入指南与端点信息

### 1. 客户端网络网关注入点
C 侧工程（`android`、`client-core`）在替换离线演示大厅的 `FakeGateway` 时，统一注入 `client-network` 提供的权威实现：
```java
com.lightchase.network.WebSocketClientGateway gateway = new com.lightchase.network.WebSocketClientGateway();
```
其实现的接口是 `contracts` 模块中唯一的 `com.lightchase.contracts.ClientGateway`。

### 2. 连接端点与网络配置
调用 `connect(ConnectionOptions, GatewayListener)` 发起连接：
```java
ConnectionOptions options = new ConnectionOptions(
    host,           // 服务端 IP 或域名
    port,           // 服务端端口（缺省默认 8080）
    roomId,         // 房间号：1..8 位大写字母或数字，如 "ROOM1"
    clientBuild,    // 客户端版本标识，如 "0.1.0"
    data.mapHash,   // 从 DataFiles 获取的当前地图 SHA-256 原始哈希
    data.configHash // 从 DataFiles 获取的规则配置 SHA-256 原始哈希
);
gateway.connect(options, listener);
```

#### 设备端点填写规范：
- **Android 官方模拟器（AVD）**：
  - 宿主机在模拟器中的回环地址固定为：`10.0.2.2`；
  - 端口填服务端监听端口（默认 `8080`）；
  - WebSocket 完整路径为：`ws://10.0.2.2:8080/game`；
  - **严禁**在模拟器内填写 `127.0.0.1`（会导致连接到模拟器自身而超时失败）。
- **真机调试（局域网 WiFi）**：
  - 手机与电脑连接同一局域网 WiFi，填写宿主机的局域网 IPv4 地址（如 `192.168.1.100`）；
  - 确认电脑防火墙允许入站连接到 Java/8080 端口；
  - 必须确认 Android targetSdk 37 已授予网络权限（`android:usesCleartextTraffic="true"` 仅限 debug 阶段）。

### 3. 线程切换与渲染主循环调度
- **回调线程注意**：
  - `GatewayListener` 的全部回调（`onConnection`, `onSession`, `onControl`, `onRoom`, `onView`, `onResult`, `onError`）串行触发，但可能来自WebSocket/定时线程，也可能同步发生于调用网关方法的线程；
  - **libGDX 的 OpenGL 渲染上下文仅在主渲染线程有效**；
  - C 侧在收到回调更新 UI、变更屏幕或释放纹理时，必须使用 `Gdx.app.postRunnable(() -> { ... })` 将逻辑投递到渲染主循环中执行。
- **输入提交（`submitInput`）**：
  - C 侧每帧只调用单参数接口：
    `InputFrame` 使用 `com.lightchase.contracts.InputFrame`。
    ```java
    gateway.submitInput(new InputFrame(moveX, moveY, interactHeld, dropPressed));
    ```
  - SUSPECT时清空触控；恢复后持续按住不会自动续动，移动须回中立，交互/drop须释放后重新操作。
  - 网关内部自动以 20Hz 有序采样，且自动处理 250ms 租约归零与 drop 瞬时脉冲单调分配，UI 侧无需手工写定时器或计算 drop 序列号。

### 4. 结算、返回大厅与重开流程
1. 收到 `onResult(MatchResult)`：UI 显示对局胜负结算对话框；
2. 用户点击“返回大厅”按钮：UI 调用 `gateway.returnToLobby()`；
3. 收到 `onControl(ControlStatus)` 确认 `RETURN_LOBBY` 成功，且随后收到 `onRoom(room)`；
4. 当 `room.phase == RoomPhase.LOBBY` 时，双方均已返回，角色槽位已自动保留，用户可直接点击“准备”（`setReady(true)`）开启全新对局！
